# 確定事項・延期範囲

状態: 承認済み

バージョン: 0.2.2

## 確定事項

### D-001 複数グループ

ユーザーは複数グループを作成・参加できる。所属はjoin entityで表現し、ユーザーに単一グループIDを持たせない。

### D-002 メンバー人数

データモデルで2人に制限しない。非公開MVPは2人を中心にテストするが、認可と負担配分は3人以上にも対応する。

### D-003 金額の意味

グループ支出、メンバー利用額、メンバー支払額、収入受取者を別の値・labelとして扱う。

### D-004 公開範囲

MVPの取引は、所属する全アクティブメンバーから閲覧できる。「自分の履歴」は絞り込みであり、非公開機能ではない。

### D-005 アーキテクチャ

単一のNext.js App Routerモジュラーモノリスとする。`src/modules`へ機能単位で配置し、サーバー専用DAL/query、Web更新用Server Action、外部境界用Route Handlerを使う。

### D-006 ローカル環境

ローカルのNext.jsと、version固定・機能縮小したSupabase互換stackをDocker Composeで起動する。ローカルstackを本番利用しない。

### D-007 本番インフラ

Next.js containerをCloud Run東京へrequest-based billing・scale-to-zeroで配置し、マネージドSupabase東京を利用する。

### D-008 バックアップ

MVPでは自動backupを実装しない。論理削除、CSV出力、高risk migration前の手動dumpを使用する。一般公開前に再検討する。

### D-009 キャッシュ

個人の家計データは標準でキャッシュしない。分離・無効化テストを追加した後だけ導入する。

### D-010 Realtime

最初の縦切りではRealtime同期を実装しない。将来eventを再取得通知として利用できる構造にする。

### D-011 仕様先行開発

今後の機能追加・仕様変更・不具合修正は、仕様作成、仕様レビュー、テスト作成、実装、検証の順で行う。この順序を`AGENTS.md`の最優先ルールとする。

### D-012 Google OAuthと非公開利用者

MVPの認証はGoogle OAuthのみとし、アプリでパスワードや認証メールを管理しない。非公開期間は環境変数で明示的に許可したアカウントだけを受け入れ、件数の上限は設けない。独自ID・パスワードは、パスワード保管と回復運用を独自に持つため採用しない。グループ招待はメール送信せず、1回限りのリンクを利用者間で直接共有する。

## 延期中のプロダクト判断

次は最初の中核縦切りを妨げないが、対象機能へ着手する前に決定する。

| ID         | 判断内容                                             | 決定期限         |
| ---------- | ---------------------------------------------------- | ---------------- |
| `OPEN-001` | アカウント削除と過去データ保持                       | 一般登録前       |
| `OPEN-003` | 利用規約・プライバシーポリシー                       | 一般登録前       |
| `OPEN-005` | CAPTCHA providerとabuse判定値                        | 一般登録前       |
| `OPEN-006` | Realtime subscription方針・上限                      | Realtime実装前   |
| `OPEN-007` | 自動backupを必須化する条件                           | 一般公開前       |
| `OPEN-008` | マネージドSupabaseの登録前フックと許可リスト投入手順 | 初回本番deploy前 |

## 延期機能

次はMVPへ中途半端な実装を入れない。

- 予算
- 定期取引のjob自動生成、週次・隔週・年次、29〜31日・月末調整、変動金額、過去月の確定値保持（固定額月次の定期取引設定は`REC-*`として実装）
- 銀行・カード連携
- レシートOCR
- 振替・残高管理
- 自動精算
- グループ横断分析
- 共有グループ内の非公開行
- 1グループ内の複数通貨
- ネイティブアプリ
- グループ削除
- Service Workerによるオフラインキャッシュ・プッシュ通知（ホーム画面インストール可能化は`NFR-PWA-*`としてMVPに含む）

延期機能は、初期コード内の未使用flagとして入れず、新しい仕様・レビューを作成してから追加する。
