# 資産推移仕様

状態: 承認済み（review: 2026-10-15-asset-tracking-spec）

バージョン: 0.1.0

対象リリース: MVP後・資産推移フェーズ

## 1. 目的

グループの各メンバーが保有する現金・預金、NISA、iDeCoなどの資産額を月ごとに記録し、グループの資産がどう推移したかを積み上げ面グラフでスマートフォンから確認できるようにする。

詳細分析の貯金額（`ANA-013`）は期間開始時を0円とした収支の累積であり、実際に保有している資産額を表さない。本機能はその不足を、**月末時点の資産額を利用者が手で記録する**方式で補う。取引から残高を自動計算する口座残高管理、口座間の振替、証券口座との連携は行わない（[`08-decisions-and-deferred-scope.md`](08-decisions-and-deferred-scope.md)の「振替・残高管理」は引き続き対象外）。

## 2. 用語

| 用語       | 意味                                                                                                             |
| ---------- | ---------------------------------------------------------------------------------------------------------------- |
| 資産区分   | 「現金・預金」「NISA」など、資産額を分類する単位。グループごとに追加・名称変更・色変更・削除（アーカイブ）できる |
| 資産記録   | 1グループ・1か月分の資産額の記録。`asset_snapshots`の1行と、その内訳`asset_snapshot_values`の行で構成する        |
| 資産額     | 1メンバー・1資産区分の、記録月の月末時点の評価額。0以上のJPY整数                                                 |
| 記録月     | 資産記録が表す月。`YYYY-MM`。グループのタイムゾーン上の当月以前に限る                                            |
| 合計資産額 | 1つの資産記録に含まれる資産額の合計                                                                              |
| 前回比     | 表示中の記録月の合計資産額と、その直前の記録月の合計資産額との差額（符号付き）                                   |

資産額は利用者が入力した値をそのまま保存する。購入元本、含み益、利回り、株価・基準価額による評価替えは扱わない。

## 3. 機能要件

- `AST-001` アクティブメンバーは、グループの資産推移と、すべてのメンバーの資産記録を閲覧できる。メンバーごとの非公開設定は設けない。
- `AST-002` アクティブメンバーは、記録月を指定して、全アクティブメンバー × 全アクティブ資産区分の資産額を1つの資産記録として保存できる。他のメンバーの資産額も入力・修正できる（取引と同じ信頼モデル）。
- `AST-003` 資産記録がまだない月の入力欄には、その月より前で最も新しい資産記録の値を初期値としてコピーする。コピー元がない場合は空欄（0円）とする。
- `AST-004` アクティブメンバーは、既存の資産記録を修正・削除できる。削除は物理削除とし、復元機能は提供しない。
- `AST-005` 資産記録の更新は楽観的lockを使い、同時編集を暗黙に上書きしない。
- `AST-006` ownerまたはadminは、資産区分を追加・名称変更・色変更・削除（アーカイブ）できる。アクティブな資産区分は最大8件とする。
- `AST-007` 資産推移は、横軸を月、縦軸を金額とする積み上げ面グラフで表示し、「区分別」「メンバー別」の積み上げを同じ領域の切替で即時に切り替えられる。
- `AST-008` 資産推移は、表示期間（6か月・1年・3年・全期間）と、区分別の対象（全員・各メンバー）を即時に切り替えられる。切替でページ全体の再読み込みやデータの再取得を行わない。
- `AST-009` グラフには資産記録のある月だけを点として描き、記録のない月の値を補完・推定しない。
- `AST-010` グラフと同じ内容を数値で確認でき、グラフを見なくても各月の合計資産額と内訳を理解できる。
- `AST-011` 資産記録と資産区分は`group_id`を持ち、RLSで別グループから閲覧・更新できない。
- `AST-012` 資産記録と取引・予算・分析・LINE週次レポートは相互に金額を変更・参照しない。

## 4. 権限

| 操作                       | owner | admin | member | 非メンバー |
| -------------------------- | ----: | ----: | -----: | ---------: |
| 資産推移・資産記録の閲覧   |    可 |    可 |     可 |       不可 |
| 資産記録の作成・修正・削除 |    可 |    可 |     可 |       不可 |
| 資産区分の追加・変更・削除 |    可 |    可 |   不可 |       不可 |

閲覧はアクティブメンバー全員に許可する。すべての更新はDBの`security definer`関数内で認証・許可リスト・アクティブ所属・権限を再確認し、テーブルへ直接の更新権限を付与しない。

## 5. 資産記録の規則

### 5.1 記録月と金額

- 記録月はグループのタイムゾーン上の当月以前とし、2000-01以降に限る。将来月の記録は作成できない。当月はその時点の値として記録してよい。判定はDB関数がグループの`timezone`から当月を求めて行い、クライアントの日時を信用しない。
- 資産額は`0`以上`9,007,199,254,740,991`以下の整数とする。負債（マイナスの資産）は扱わない。金額計算に浮動小数点を使わない。
- 同じグループ・同じ記録月の資産記録は1件だけとする。

### 5.2 保存の単位

- 資産記録は記録月ごとに1回の保存操作で、全アクティブメンバー × 全アクティブ資産区分の資産額をまとめて保存する。メンバーごとに別々に保存する操作は設けない。
- 空欄は0円として保存する。資産額が0円のセルは`asset_snapshot_values`へ行を作らず、行がないセルを0円として扱う。
- 保存する値の組は、保存時点のアクティブメンバーとアクティブ資産区分に限る。それ以外のメンバー・資産区分を含む要求は拒否する。
- 既存の資産記録を修正する場合、保存時点でアクティブでないメンバー（削除済み所属）またはアーカイブ済みの資産区分の資産額は変更せず、そのまま保持する。保存操作で置き換えるのは、アクティブメンバー × アクティブ資産区分のセルだけとする。

### 5.3 前回値のコピー（`AST-003`）

- 資産記録がない記録月の入力画面を開いたとき、入力欄の初期値は、その記録月より前で最も新しい資産記録（コピー元）の、同じメンバー・同じ資産区分の資産額とする。コピー元にない組み合わせ（新しいメンバー・新しい資産区分）は空欄とする。
- コピーは入力欄の初期値にするだけで、保存操作をするまでDBへ資産記録を作らない。記録のない月を自動で作らない。
- コピーした場合は入力欄の上に「{YYYY}年{M}月の記録をコピーしました。変わった金額だけ直して保存してください。」を表示する。コピー元がない場合は「最初の記録です。各メンバーの資産額を入力してください。」を表示する。
- 既存の資産記録がある記録月を開いたときは、その記録の値を初期値にし、コピーの案内は表示しない。

### 5.4 削除

- 資産記録の削除は記録月単位で行い、その月の`asset_snapshots`と内訳を同一transactionで物理削除する。他の月の資産記録とコピー元の判定は、残った資産記録だけで行う。
- メンバーの削除（所属の`removed`）や資産区分のアーカイブは、既存の資産記録を変更しない。

## 6. 資産区分

- 資産区分は名称（前後空白を除いて1〜20文字）、色、並び順を持つ。同じグループのアクティブな資産区分の間で名称を重複させない。
- 色はカテゴリと同じ18色のtoken（`AC-CAT-002-7`）から選ぶ。tokenと色値の対応は`src/app/styles.css`の共通定義を使い、資産側で色値を再定義しない。
- 並び順は作成順とし、グラフの積み上げは並び順の先頭を最下段にする。並び替え操作は初回実装では提供しない（§12）。
- グループ作成時と、本機能のmigration時点で既存のグループには、次の4区分を初期作成する。

| 並び順 | 名称       | 色token  |
| -----: | ---------- | -------- |
|      1 | 現金・預金 | `sky`    |
|      2 | NISA       | `orange` |
|      3 | iDeCo      | `mint`   |
|      4 | その他投資 | `indigo` |

- 削除はアーカイブとし、物理削除しない。アーカイブ済みの資産区分は入力画面へ表示しないが、過去の資産記録の資産額は推移グラフ・数値に引き続き含め、現在の名称・色で表示する。
- アクティブな資産区分は最大8件とする。8件あるときは追加操作を無効化し、理由を表示する。アーカイブ済みを含めた総数は最大30件とする。
- アーカイブ済みの資産区分は、アクティブ件数が8件未満であれば元に戻せる。

## 7. 画面仕様

### 7.1 入口とナビゲーション

- 資産推移の標準URLは`/groups/{groupId}/assets`とし、共通ナビゲーションの現在地は「分析」とする。主要ナビゲーションの項目数は変えない。
- 概要分析と詳細分析の画面下部（カテゴリ別支出の後）に「資産推移」へのリンク行を置く。資産推移からは概要分析へ戻れる。
- 設定ハブの「グループ管理」に「資産区分」行を追加し、owner/adminにだけ表示する。

### 7.2 資産推移（`/groups/{groupId}/assets`）

375 x 812では次の順に縦配置し、最新の合計資産額と推移グラフを最初のスクロール前に確認できることを目標とする。

1. 見出し「資産推移」と「資産を記録」ボタン（当月の記録画面へ遷移。44 x 44 CSS pixel以上）
2. 選択中の記録月の合計資産額（`￥12,345,678`）と前回比（符号付き。前回の記録がなければ表示しない）。初期の選択月は最新の記録月
3. 表示条件: 表示期間（「6か月」「1年」「3年」「全期間」）と、積み上げ（「区分別」「メンバー別」）の切替。区分別のときだけ対象（「全員」と各アクティブメンバー、削除済みでも記録のあるメンバー）の選択欄を表示する
4. 積み上げ面グラフと凡例（凡例はグラフの下。色の印と系列名を並べ、幅に応じて折り返す）
5. 選択中の記録月の内訳: 系列ごとに色の印、名称、正確な金額、構成比を1行で並べる（区分別ではその月の区分ごとの合計、メンバー別ではメンバーごとの合計）
6. 「月別の資産額」一覧: 表示期間内の記録月を新しい順に、記録月・合計資産額・前回比を1行で並べる。各行は選択ボタンと「修正」リンク（その月の記録画面）を持つ

- 表示期間・積み上げ・対象・選択月の切替はClient Componentのローカル状態だけで行い、URL・DB・localStorageへ保存しない。サーバーへの再取得、ページ全体の再描画、スクロール位置の移動を伴わず、タップ直後に描画を切り替える。再読み込み後は既定（1年・区分別・全員・最新の記録月）へ戻ってよい。
- 表示期間は、最新の記録月を終了月とし、終了月を含む直近6か月・12か月（1年）・36か月（3年）の範囲とする（例: 終了月が2026-10の1年は2025-11〜2026-10）。全期間は最古の記録月から終了月までとする。範囲内の記録月だけを表示し、既定は1年とする。
- 選択月は、グラフのタップ位置に最も近い記録月、または「月別の資産額」の行の選択で変更する。表示期間を変えて選択月が範囲外になった場合は範囲内の最新の記録月を選択する。
- 金額は省略せず`￥`付きで表示する。グラフの縦軸ラベルだけは「6,000万円」「500万円」のように万円単位の短縮表記を使ってよい（直近に正確な合計資産額を表示しているため）。
- 空状態（資産記録が1件もない）では、グラフと表示条件を表示せず、「資産の推移を記録すると、ここにグラフが表示されます。」と「資産を記録」ボタンを表示する。
- 1280 x 800では、合計・表示条件・グラフを左カラム、選択月の内訳・月別の資産額を右カラムへ配置してよい。コンテンツは過度に横へ伸ばさない。

### 7.3 積み上げ面グラフ（`AST-007`、`AST-009`）

- 横軸は表示期間内の月を暦どおりの等間隔に並べ、縦軸は0円から表示期間内の合計資産額の最大値までとする。縦軸の上端は最大値以上の切りのよい値（1・2・5 × 10の累乗万円）へ切り上げ、上端と中間の目盛りに短縮表記のラベルを付ける。全記録が0円のときも0除算を起こさず、基準線だけを描く。
- 各系列は並び順（区分別は資産区分の並び順、メンバー別は表示順）に下から積み上げ、各記録月の累積値を点として、隣り合う記録月の点を直線で結んだ面で描く。記録のない月には点を置かず、前後の記録月を結ぶ直線は補間した値を表示・数値化しない。グラフの下に「点のある月が記録した月です。間の月は記録がありません。」を小さく注記する（記録のない月が範囲内にある場合だけ）。
- 記録月が表示期間内に1件だけの場合は、その月の位置に積み上げた縦棒（幅24px以下）として表示する。
- 選択中の記録月には縦の補助線を引き、内訳（§7.2の5）と対応させる。
- メンバー別の系列は表示順のメンバー（自分を先頭、続いてアクティブメンバーの参加順、最後に削除済みメンバーの参加順）とし、色は18色tokenの`food`から順に割り当てる。区分別は各資産区分の色を使う。ダークテーマでもカテゴリ色と同じtoken定義を使い、資産側で色値を直書きしない。
- 削除済みメンバーの系列名は表示名の後に「（退出）」を付ける。
- グラフは`aria-hidden`の装飾とし、hoverやtooltipに情報を置かない。同じ値を内訳と「月別の資産額」で確認できる。グラフ領域のタップは選択月の変更だけを行う。
- 区分別で対象にメンバーを選んだときは、そのメンバーの資産額だけを区分別に積み上げる。合計資産額・前回比・内訳・月別の資産額もそのメンバーの値に切り替える。
- 系列の座標（点の位置、積み上げ値、縦軸の上端と目盛り）と前回比・構成比は資産moduleの純関数で求め、Client Componentは純関数の結果を描くだけにする。構成比は整数パーセントへ四捨五入した表示値とし、金額計算に使わない。

### 7.4 資産の記録（`/groups/{groupId}/assets/record?month=YYYY-MM`）

`month`未指定はグループのタイムゾーン上の当月とする。共通ナビゲーションの現在地は「分析」とする。

375 x 812では次の順に縦配置する。

1. 記録月と前月・翌月操作（44 x 44 CSS pixel以上。翌月操作は当月で無効化する）
2. コピーの案内（§5.3）、または既存記録の最終更新者と更新日時
3. メンバーごとのまとまり: 見出しにメンバーの表示名と小計、その下にアクティブ資産区分の並び順で「区分名」と金額欄を1行ずつ並べる。自分を先頭にし、続けてアクティブメンバーを参加順に並べる
4. 合計資産額（入力中に即時更新）
5. 「保存する」ボタン。既存記録があれば、その下に「この月の記録を削除」

- 金額欄は`inputmode="none"`とし、予算フォーム（`AC-BUD-010-4`・`AC-BUD-010-5`）と同じ画面内テンキーと3桁区切り表示で入力する。テンキーと整形関数は`transactions`モジュールの公開エントリーポイント経由で共有し、資産側へ複製しない。送信する値は区切りなしの整数をhidden inputで送る。
- 小計と合計は区切りなしの入力状態から計算し、表示だけを整形する。
- 保存成功時は資産推移（`/groups/{groupId}/assets`）へ遷移し、最新の記録月を選択した状態で表示する。遷移後の画面上部に、取引保存（`TXN-019`）と同じ仕組みのトーストで「{YYYY}年{M}月の資産を保存しました」を表示する。削除成功時も同様に「{YYYY}年{M}月の資産記録を削除しました」を表示する。
- 記録月を変えたときは、遷移先の月の初期値（既存記録またはコピー）へ入力を初期化し、別の月の未保存入力を持ち越さない。
- 削除は「この月の記録を削除」を押した後に、確認文「{YYYY}年{M}月の資産記録を削除します。元に戻せません。」と確定操作を表示し、確定で削除して資産推移へ遷移する。
- 入力不備は該当欄の近く、権限不足・競合・通信失敗はフォーム全体のエラーとして表示する。競合時は他のメンバーが先に保存・削除した旨と再読み込みを案内し、入力中の値を破棄しない。保存中は主要ボタンを無効化する。
- 将来月、2000-01より前、不正な形式の`month`は資産記録を読み込まずに検証エラーと当月へ戻る導線だけを表示する。
- アクティブな資産区分が0件の場合は入力欄を表示せず、owner/adminには資産区分の管理画面への導線、memberには「資産区分はオーナーと管理者が設定します。」を表示する。
- 1280 x 800では、メンバーごとのまとまりを2カラムへ並べてよい。

### 7.5 資産区分の管理（`/groups/{groupId}/asset-categories`）

owner/adminだけが開ける。共通ナビゲーションの現在地は「設定」とする。memberが直接URLを開いた場合は権限不足として拒否し、資産区分データを返さない。

- アクティブな資産区分を並び順で1区分1行（色の印、名称、「編集」）に並べ、その下に追加フォーム（名称、色）を置く。
- 「編集」は行内に編集パネルを開き、名称と色を1つの保存操作で変更する。色はカテゴリ管理と同じswatchで選ぶ。編集パネルは同時に1行だけ開く。
- 編集パネルの「削除」は、確認文（過去の資産記録の表示と合計は変わらないこと、入力画面から外れること）を提示し、明示的な確認操作を経てアーカイブする。
- アーカイブ済みの資産区分は「削除した区分」として折りたたみ内に一覧し、「元に戻す」を提供する。
- アクティブが8件のときは追加フォームの送信と「元に戻す」を無効化し、「資産区分は8件まで登録できます。」を表示する。

## 8. データモデル

### `asset_categories`

| column        | 型                   | 説明                      |
| ------------- | -------------------- | ------------------------- |
| `id`          | uuid PK              |                           |
| `group_id`    | uuid FK              | 必須のグループ境界        |
| `name`        | text                 | 前後空白を除いて1〜20文字 |
| `color`       | text                 | カテゴリと同じ18色token   |

| `updated_by`  | uuid FK              | 認証ユーザー              |
| `created_at`  | timestamptz          | UTC                       |
| `updated_at`  | timestamptz          | UTC                       |

制約:

- `(id, group_id)`をuniqueにし、内訳から複合外部キーで参照できるようにする。
- `(group_id, sort_order)`をuniqueにする。
- `archived_at is null`の行について`(group_id, lower(name))`をpartial uniqueにする。
- `color`は18色tokenのいずれかに限る。
- アクティブ8件・総数30件の上限はDB関数で検証する。

### `asset_snapshots`

| column       | 型          | 説明                      |
| ------------ | ----------- | ------------------------- |

- `(group_id, month)`をuniqueにする。
- `(id, group_id)`をuniqueにする。
- `month`は月初日（`date_trunc('month')`と一致）かつ`2000-01-01`以上に限る。当月以前の判定はタイムゾーンに依存するためDB関数で行う。

## 9. サーバー境界

`src/modules/assets`を新設し、公開エントリーポイント経由でだけ他機能から利用する。

```text
Query:   getAssetTrend(groupId)                          // 資産推移画面のDTO
         getAssetRecordForm(groupId, searchParams)        // 記録画面の初期値（既存記録またはコピー）
         getAssetCategorySettings(groupId)                // 資産区分の管理画面
Command: saveAssetSnapshot(groupId, month, expectedVersion | null, values)
         deleteAssetSnapshot(groupId, month, expectedVersion)
         createAssetCategory(groupId, name, color)
         updateAssetCategory(groupId, categoryId, expectedVersion, name, color)
         archiveAssetCategory(groupId, categoryId, expectedVersion)
         restoreAssetCategory(groupId, categoryId, expectedVersion)
Pure:    buildAssetTrendSeries(dto, { range, stack, memberId })  // 系列・座標・縦軸・前回比・構成比
```

- 各queryは`groupId`と`month`を検証し、共有境界`resolveGroupReadContext`で認証・アクティブ所属を確認する。未認証は`next`付きログインへ、非メンバー・不正な`groupId`は存在を明かさず`null`を返す。
- `getAssetTrend`はグループのすべての資産記録の値（記録月、メンバー、資産区分、金額）、資産区分（アーカイブ済みを含む名称・色・並び順）、表示に必要なメンバー（アクティブメンバーと、記録に現れる削除済みメンバーの表示名・表示順）を1回で返す。表示期間・積み上げ・対象の切替はこのDTOに対してClient Componentが純関数`buildAssetTrendSeries`を呼んで行い、サーバーへ再取得しない。全期間で記録月が600件（50年）を超えるデータは想定しないが、DTOの件数上限として記録月600件をqueryで打ち切る。
- `buildAssetTrendSeries`は資産moduleのdomain層に置く副作用のない純関数とし、Server ComponentとClient Componentの双方から呼べるよう`server-only`を含めない。金額は整数で計算し、座標だけを表示用の数値へ変換する。
- `getAssetRecordForm`は記録月の既存記録があればその値と`version`を、なければ記録月より前で最も新しい資産記録の値をコピー元の記録月とともに返す。返す入力欄はアクティブメンバー × アクティブ資産区分に限る。
- 各commandはServer Actionで入力をschema検証したうえで、`security definer`のDB関数（`save_asset_snapshot`、`delete_asset_snapshot`、`create_asset_category`、`update_asset_category`、`archive_asset_category`、`restore_asset_category`）を1回呼び、同一transactionで保存する。DB関数は許可リスト・アクティブ所属・権限（資産区分はowner/admin）、記録月の範囲（当月以前・2000-01以降）、金額範囲、値の組がアクティブメンバー × アクティブ資産区分に含まれ重複しないこと、`expectedVersion`、資産区分の件数上限と名称の重複を再検証する。
- `save_asset_snapshot`は`expectedVersion`が`null`なら新規作成（同月の記録が既にあれば競合）、値があれば同じ`version`の既存記録の更新（存在しない・versionが古いなら競合）とする。更新では要求に含まれるアクティブメンバー × アクティブ資産区分のセルだけを置き換え、それ以外のセルを保持する（§5.2）。要求内容が現在の値と同じ場合は更新も`version`の加算も行わず成功として返す（再送の冪等性）。
- クライアントが渡した合計資産額、小計、前回比、メンバーの権限・所属を信用しない。
- DB関数の失敗は`40001`（競合）、`P0002`（対象なし）、`42501`・`28000`（権限不足・未認証）、`22023`（入力不正）、`23505`（同月の同時作成・名称重複。前者は競合として扱う）を分類して利用者向けメッセージへ変換し、サーバーlogへ操作名とcodeだけを記録する（`NFR-OPS-008`）。資産額をlogへ出さない。
- グループ作成のDB関数は、カテゴリの初期作成と同じtransactionで資産区分の初期4区分を作成する。既存グループへはmigrationで同じ4区分を作成する。
- Server Componentはサーバー専用queryを直接呼び、Client Componentへは最小DTOだけを渡す。DB行、ユーザーID、tokenを渡さない。メンバーは表示用の識別子（`group_members.id`）と表示名だけを渡す。
- 個人の家計データに対する共有cacheを追加しない。

## 11. テスト方針

- 単体: `buildAssetTrendSeries`（積み上げ順、記録のない月を補完しないこと、1件だけの表示、0円だけの記録、縦軸の切り上げ、表示期間の境界、対象メンバーの絞り込み、前回比と構成比の整数丸め）、コピー初期値の組み立て、金額入力の検証schema
- DB統合・RLS: 別グループの資産記録・資産区分を閲覧・更新できないこと、memberが資産区分を変更できないこと、テーブルへの直接更新が拒否されること、将来月・範囲外の金額・非アクティブなメンバーや資産区分を含む保存の拒否、楽観的lockの競合、更新時に削除済みメンバー・アーカイブ済み区分のセルが保持されること、件数上限と名称重複
- E2E: 初回記録 → 翌月のコピー初期値 → 一部修正して保存 → 推移グラフと月別の資産額への反映、区分別・メンバー別・表示期間の切替で再取得が発生しないこと、削除の確認
- 画面確認: 320px、375 x 812、1280 x 800、iOS Safari（Simulator）での記録画面のテンキーと推移グラフ

## 12. 初回実装から延期する範囲

- 資産区分の並び替え
- 負債（ローン残高など）とマイナスの資産額
- 購入元本・含み益・利回りの記録と表示
- 証券会社・銀行との連携、株価・基準価額による自動評価
- メンバーごとの資産の非公開設定（必要になった場合は個人グループで扱うことを第一候補とする）
- 記録月より細かい（日次・週次の）記録
- 資産記録のCSV出力・復元、LINE週次レポートへの掲載
- 資産記録の未入力を知らせる通知
- 取引の収支との突き合わせ（資産の増減と貯金額の比較）
