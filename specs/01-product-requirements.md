# プロダクト要件

状態: 承認済み

バージョン: 0.3.4

## 1. プロダクト概要

個人が複数の家計グループを作成または参加し、グループ内の収入・支出を記録できる、スマートフォン優先のWebアプリを構築する。月間カレンダーと取引履歴により、グループ全体およびメンバー別の支出をすぐに把握できるようにする。

最初の実利用者は夫婦2人だが、無関係な一般ユーザーがそれぞれ独立したグループを作成しても、データが混在・漏えいしない認可・データモデルとする。

## 2. プロダクト原則

1. よくある支出は、入力画面を開いてから通常10秒以内で登録できることを目標とする。
2. ホーム画面だけで「このグループが今日・今月いくら使ったか」が分かる。
3. 「誰が登録したか」「誰が支払ったか」「誰の負担か」を別の概念として扱う。
4. 画面操作の便利さより、グループ間のデータ分離を優先する。
5. MVPは小さく始めるが、グループが2人限定になる設計を入れない。

## 3. 用語

| 用語           | 定義                                                |
| -------------- | --------------------------------------------------- |
| ユーザー       | 認証済みアカウント。複数グループを作成・参加できる  |
| グループ       | 家庭、旅行などの独立した家計管理単位                |
| メンバー       | あるグループにおけるユーザーの所属情報              |
| 操作者         | レコードを登録または最後に更新したユーザー          |
| 支払者         | MVPにおいて支出を支払ったアクティブメンバー         |
| 受取者         | MVPにおいて収入を受け取ったアクティブメンバー       |
| 負担額         | 支出のうち、あるメンバーへ割り当てられた金額        |
| グループ支出   | 選択中グループにおいて、1取引を一度だけ数えた支出額 |
| メンバー支出   | 選択メンバーへ割り当てられた負担額の合計            |
| メンバー支払額 | 選択メンバーが支払者である支出額の合計              |
| 取引日         | 取引を集計する、グループのタイムゾーン上の日付      |

## 4. 権限

| 権限   | できること                                              |
| ------ | ------------------------------------------------------- |
| owner  | グループ、メンバー、設定、全取引を管理する              |
| admin  | メンバー招待、グループ取引、カテゴリを管理する          |
| member | グループデータを閲覧し、MVPルールに従って取引を操作する |

MVPでは、アクティブメンバーはグループ内の全取引を編集・削除できる。監査情報に操作者を記録する。共有家計での操作性を優先し、登録者だけに編集を制限する仕様は延期する。

ownerだけが所有権を変更できる。ownerはアクティブなadminまたはmemberをownerへ昇格できる。別のアクティブownerが残る場合のみ、ownerの降格・脱退・削除を許可する。グループ削除はMVP対象外とする。

## 5. MVP機能要件

### 認証

- `AUTH-001` 許可された未登録ユーザーは、Google OAuthによる初回ログインで登録できる。
- `AUTH-002` ログインユーザーは表示名を持つプロフィールを利用できる。
- `AUTH-003` すべてのアプリ画面からログアウトできる。
- `AUTH-004` 未認証で保護画面へアクセスした場合、ログイン画面へ遷移する。
- `AUTH-005` アプリはGoogle OAuth以外のログイン方法を提供せず、パスワードや認証メールを保管・送信しない。
- `AUTH-006` Googleログインを開始するたびにGoogleのアカウント選択画面を表示し、ブラウザに残った別のGoogleアカウントのsessionで意図せずログインされない。ログアウト後に別の許可済みGoogleアカウントへ切り替えられる。

MVPの認証方式はGoogle OAuthのみとする。メールアドレス・パスワード、magic link、OTP、電話番号による認証画面・Action・メール送信基盤は持たない。非公開MVPでは、Git管理外のサーバー環境変数に正規化したGoogleアカウントを1件以上明示的に設定し、その許可リストに含まれるアカウントだけに登録・ログイン・データアクセスを許可する。件数の上限は設けず、利用者の追加は環境変数の更新だけで行う。「先着n人」は使わない。OAuth設定または許可リストが不完全な環境ではログインを無効化し、理由を明示する。

OAuth開始時、Docker内部またはprivate network専用のSupabase URLをブラウザへ返さない。Auth clientが生成した認可URLのoriginとpathを検証し、承認済みの公開Supabase URLへ変換してから遷移する。想定外のURLは拒否する。

Google OAuthの開始は、ブラウザの通常のtop-level HTTP navigationで専用Route Handlerへ要求する。Route HandlerはPKCE verifier cookieを含む応答を確定してからSupabase Authへredirectし、JavaScriptで拡張されたServer Actionの外部redirectにcookie確定を依存しない。

OAuth開始要求のoriginが構成済みの公開サイトoriginと異なる場合、Route HandlerはPKCE cookieを発行する前に、検証済みの戻り先だけを維持して公開サイトorigin上の同じ開始Routeへredirectする。PKCE cookieを保存するhostとアプリcallbackのhostを一致させ、`localhost`、IP address、別portなどの表記差でcode交換が失敗しないようにする。

### グループとメンバー

- `GRP-001` ユーザーは複数グループを作成できる。
- `GRP-002` ユーザーは複数グループへ所属できる。
- `GRP-003` ユーザーは操作対象のグループを切り替えられる。
- `GRP-004` ownerまたはadminは、1回限り・有効期限付きの共有用招待リンクを作成できる。
- `GRP-005` 認証済みの招待対象ユーザーは、招待を承認してアクティブメンバーになれる。
- `GRP-006` アクティブメンバーでないユーザーは、対象グループを閲覧・更新できない。
- `GRP-007` ownerは、所有権制約の範囲でメンバー権限を変更できる。
- `GRP-008` ownerは、owner以外のメンバーを削除できる。
- `GRP-009` グループは、名称、通貨、タイムゾーン、週の開始曜日、標準負担方法を持つ。
- `GRP-010` グループには常に1人以上のアクティブownerが存在する。
- `GRP-011` アクティブな所属グループが1件だけのユーザーは、ログイン後やホーム（`/app`）到達時にグループ選択を経由せず、そのグループの当月カレンダーへ直接遷移できる。グループ一覧・プロフィール・グループ作成へは設定などの明示的な導線から引き続き到達できる。
- `GRP-012` ユーザーはアクティブに所属するグループの1つを「起動時に開くグループ」として設定・解除できる。設定中は所属件数にかかわらず、ログイン後やホーム（`/app`）到達時にグループ選択を経由せずそのグループの当月カレンダーへ直接遷移する。設定はユーザーごとに1件で、他のメンバーへ影響しない。

MVP制約:

- 通貨はグループごとに保存するが、動作とテストはJPYだけを対象とする。
- 標準タイムゾーンは`Asia/Tokyo`とする。
- 招待の標準有効期限は72時間とし、アプリからメール送信せず利用者が安全な手段で直接共有する。
- 招待トークンはハッシュだけを保存する。
- 共有リンクの生トークンはURL fragmentに格納し、HTTP request path、query、cookie、永続storageへ含めない。

### カテゴリ

- `CAT-001` 新規グループには、編集可能な収入・支出の初期カテゴリを作成する。
- `CAT-002` ownerまたはadminは、グループカテゴリを追加、名称変更、並び替え、アーカイブできる。
- `CAT-003` カテゴリをアーカイブしても、過去の取引内容は変更しない。

新規グループの初期カテゴリは、支出を「食費、日用品、住居、光熱費、交通、娯楽、その他」、収入を「給与、臨時収入、その他」とし、この順序で作成する。各カテゴリは作成後に名称変更・並び替え・アーカイブできる。

### 取引

- `TXN-001` アクティブメンバーは支出を登録できる。
- `TXN-002` アクティブメンバーは収入を登録できる。
- `TXN-003` 取引は、金額、取引日、カテゴリ、種別に応じた支払者または受取者、任意メモを持つ。
- `TXN-004` 操作者は認証セッションから決定し、クライアント入力を受け付けない。
- `TXN-005` 支出の負担額合計は取引金額と一致しなければならない。
- `TXN-006` 支出は1人以上のアクティブメンバーへ割り当てられる。
- `TXN-007` グループ設定と入力内容に従い、「均等割り」または「1人負担」を標準値にできる。
- `TXN-008` アクティブメンバーはグループ取引を編集できる。
- `TXN-009` アクティブメンバーは取引を削除できる。削除は物理削除とし、アプリ内の復元機能は提供しない。
- `TXN-011` 同じ`client_request_id`で再送しても取引を重複作成しない。
- `TXN-012` 編集時はversionを使い、古い状態からの更新を暗黙に上書きせず競合として返す。
- `TXN-013` 支出にはアクティブな支払者と負担額を設定し、収入にはアクティブな受取者を設定する。MVPの収入に負担額は設定しない。
- `TXN-014` 取引入力の金額は画面内のテンキーで入力し、OSの仮想キーボードでカテゴリ選択や保存操作を隠さない。テンキーは金額欄を選んだときに開き、他の入力欄を選んだときに閉じる。
- `TXN-016` 保存操作は、テンキーの開閉やカテゴリの展開状態にかかわらず、入力ドック内へ常に表示する。
- `TXN-015` 取引入力のカテゴリは既定で1行に表示し、「すべて」操作で全件を展開して選べる。
- `TXN-017` 取引入力のテンキーは四則演算（+、−、×、÷）と=を備え、金額欄で式を組み立てて計算結果を金額として保存できる。

### 固定費（MVP後・固定額月次）

- `REC-001` ownerまたはadminは、固定額・月次の固定費（支出・収入）を作成できる。
- `REC-002` 固定費は、毎月同じ日付（1〜28日）、開始月、任意の終了月を持つ。
- `REC-003` 支出の固定費はアクティブな支払者と負担額を持ち、負担額合計を金額と一致させる。収入はアクティブな受取者を持ち、負担額を持たない。
- `REC-004` ownerまたはadminは固定費を編集・終了でき、memberは閲覧だけできる。
- `REC-005` 固定費を対象月へ展開し、ホームカレンダーの月間集計・日別表示へ単発取引と重複せずに含める。
- `REC-006` 展開は開始月から終了月までに限り、対象期間外の月へ表示・集計しない。
- `REC-007` 固定費の作成・編集・終了は、確定済みの単発取引を変更しない。
- `REC-008` 固定費の表示・集計にjob、scheduler、queue、retry、occurrence保存テーブルを使わない。
- `REC-009` 展開された取引と単発取引を画面上で識別できる。
- `REC-010` 固定費の金額は、取引入力と同じ画面内テンキーで入力し、OSの仮想キーボードによって下部ナビゲーションや入力欄の配置を崩さない。

詳細は[`14-recurring-transactions.md`](14-recurring-transactions.md)を正本とする。

### カレンダーと集計

- `CAL-001` ホーム画面に、選択中グループの月間カレンダーを表示する。
- `CAL-002` 各日付に、その日のグループ支出合計を省略・丸めせず、桁区切りした10進数字で表示する。
- `CAL-003` 支出が0円の日には金額を表示しない。
- `CAL-004` カレンダー対象を、グループ全体、自分の支出、別メンバーの支出に切り替えられる。
- `CAL-005` 日付をタップすると、その日の取引一覧を表示する。
- `CAL-006` 前月・翌月へ移動できる。
- `CAL-007` 選択月をURLへ含め、再読み込みやURL共有でも同じ月を表示する。
- `CAL-008` 選択中対象の月間支出合計を表示する。
- `CAL-009` 標準カレンダーの支出額に収入を含めない。
- `CAL-010` カレンダーの月間集計はメンバーが実際に負担した額を「支出」として統一し、立て替えた支払額を集計領域へ表示しない。支払額は履歴の絞り込みとCSVで確認する。
- `CAL-011` 同じ月・集計対象内の日付選択は、カレンダー本体を待機表示へ置き換えず即時に反映し、月間データを再取得せずに日別取引を切り替える。
- `CAL-012` カレンダーは日別・月間の収入を、支出と視覚的に区別できる形（収入用の色と「＋」表記）で表示する。日付セルでは収入と支出を合算せず、それぞれの金額を示す。
- `CAL-013` 月間の集計領域へ、選択中の月・集計対象における支出合計、収入合計、収支差額（収入 − 支出）を表示する。差額は符号を明示し、黒字・赤字を色だけで伝えない。
- `CAL-014` 表示月が当月でないとき、ホームに「今日」操作を表示し、現在の集計対象（`scope`・`member`）を維持したままグループのタイムゾーン上の当月へ戻れる。当月表示中は操作を表示せず、操作の有無で画面の高さを変えない。
- `CAL-016` カレンダーの日番号は、土曜日を薄い青、日曜日を薄い赤で表示して平日と区別する。色を変えるのは日番号だけとし、曜日見出し・セル背景・金額の色は変えない。色は曜日見出しの文字による識別の補助とし、今日・選択日・選択月外の表現と、日番号・金額の配置を変えない。

### ナビゲーション

- `NAV-001` 選択中グループの主要画面では、ホーム、履歴、入力、分析、設定の5項目へ一貫して移動できる。
- `NAV-002` ホームは選択中グループの月間カレンダーとし、通常の375 x 812 CSS pixelでは初期表示を縦スクロールせず42日分確認できる。
- `NAV-003` 入力は他のナビゲーション項目と同じデザインで表示し、視覚的に特別扱いしない。
- `NAV-004` プロフィール、グループ切替・作成、メンバー、カテゴリ、固定費、予算、CSV出力、グループ設定、ログアウトの入口を設定へ集約し、メンバーを独立した主要ナビゲーション項目にしない。

### 履歴

- `HIS-001` 選択中グループの取引を新しい順に閲覧できる。
- `HIS-002` 月、取引種別、カテゴリ、支払者、受取者、負担メンバーで絞り込める。
- `HIS-003` 履歴のshortcut chipは「自分が負担」だけを表示し、自分へ負担額が割り当てられた支出を選択する。「自分の利用」「自分が支払った」のchipは表示しない。
- `HIS-004` 負担メンバーで絞り込んだ履歴は、対象メンバーの負担額を主金額として表示し、取引全体の金額を補足する。
- `HIS-005` 履歴はcursor paginationを使用し、offset paginationを使用しない。

### 統計・分析（MVP後）

- `ANA-001` アクティブメンバーは選択グループの概要分析を閲覧できる。
- `ANA-002` 概要分析は選択月の支出、収入、収支を正確なJPY整数で表示する。
- `ANA-003` 概要分析は前月との差額を符号付きで表示する。前月に対する比率は表示しない。
- `ANA-004` 概要分析は支出カテゴリ上位5件と残りの合計を表示する。
- `ANA-005` 概要分析は選択月を前月・翌月へ変更でき、月と集計対象をURLへ保持する。
- `ANA-006` 詳細分析は3か月、6か月、12か月、および最大24か月の任意月範囲を選択できる。
- `ANA-007` 詳細分析はグループ全体、自分、指定メンバーを分析対象にできる。
- `ANA-008` 詳細分析は期間指標、月別の支出・収入・収支推移、カテゴリ別支出、メンバー別の負担額・支払額・受取額を表示する。
- `ANA-009` グラフと同じ内容を数値で確認でき、グラフを見なくても値と意味を理解できる。
- `ANA-010` 収入を支出、メンバー負担額、メンバー支払額へ混入させない。
- `ANA-011` 予算機能が有効な月だけ、概要分析に予算消化額・残額・消化率を表示する。
- `ANA-012` 詳細分析と定期レポートは、画面と同じ認可済み集計サービスを利用し、別実装で金額を再計算しない。
- `ANA-013` 詳細分析は期間の開始月から各月までの収支（収入−支出）の累積和を、貯金額の推移として棒グラフと数値で表示する。

### 予算（MVP後）

詳細は[`13-budget-management.md`](13-budget-management.md)を正本とする。

- `BUD-001` ownerまたはadminは、適用開始月を指定してグループ月間予算を設定できる。
- `BUD-002` ownerまたはadminは、グループ予算の内訳として支出カテゴリ別予算を設定できる。
- `BUD-003` アクティブメンバーは予算額、実績、残額、消化率を閲覧できる。
- `BUD-004` 予算実績はグループ支出を1取引につき1度だけ数え、収入と負担額を含めない。
- `BUD-005` 予算は適用開始月から後続月へ継続し、後の改定が過去月の予算を変更しない。
- `BUD-006` ownerまたはadminは現在月または将来月から予算を改定・停止できる。
- `BUD-007` 予算到達率が80%未満、80%以上100%未満、100%以上の状態を、色だけに依存せず表示する。
- `BUD-008` 予算超過中でも、有効な取引の登録・編集を拒否しない。
- `BUD-009` 予算更新は楽観的lockを使い、同時編集を暗黙に上書きしない。
- `BUD-010` 分析概要と予算画面は同じ実績集計定義を利用し、同じ月の予算・実績・残額が一致する。

詳細は[`12-analytics-and-reporting.md`](12-analytics-and-reporting.md)を正本とする。

### LINE週次レポート（MVP後）

詳細は[`16-line-weekly-report.md`](16-line-weekly-report.md)を正本とする。

- `NOTIF-001` 毎週日曜21:00（Asia/Tokyo）に、LINE連携済みの家計グループの週次レポートをLINEグループトークへテキスト1通でpush通知する。
- `NOTIF-002` 通知内容は、対象週の支出合計・件数・前週との差額（符号付き。比率は表示しない）・支出カテゴリ上位5件と「その他のカテゴリ」、対象月の支出・収入・収支、予算が設定されている対象月だけ予算額・消化率・残額・状態と注意または超過状態のカテゴリ予算とする。個人名、支払者・負担者の別、メモ、個別明細は含めない。
- `NOTIF-003` 集計は画面と同じ定義・同じ純関数で行い、固定費はカレンダーと同じ規則で展開して含める。対象月の支出・収入・収支は同じ月・グループ対象の概要分析・ホームカレンダーと一致し、予算進捗は予算画面と同じ純関数で計算する。送信後の取引変更は反映せず、再送しない。
- `NOTIF-004` LINE連携は、botを対象のLINEグループへ招待した際のjoin eventをWebhookで受信して登録し、leave eventで解除する。初回スコープでは家計グループ1件との単一対応とし、対象の家計グループIDはGit管理外のサーバー環境変数で指定する。
- `NOTIF-005` LINE Webhookは`X-Line-Signature`（channel secretによるHMAC-SHA256）を定数時間比較で検証し、検証失敗・未設定時は本文を処理しない。
- `NOTIF-006` 週次ジョブのエンドポイントはCloud SchedulerのOIDCトークン（Google署名、audience、呼び出しservice accountのemail）を検証し、検証失敗・未設定時は実行しない。
- `NOTIF-007` 通知処理のDBアクセスは通知専用ロールで行う。ロールは通知用の`security definer`関数のEXECUTE権限のみを持ち、テーブルへの直接権限を持たない。関数は集計に必要な最小の列だけを返し、個人名・メモ・支払者・負担者を返さない。Supabaseのservice role keyは導入しない。
- `NOTIF-008` 同一の家計グループ・対象週に対する通知は1回だけ送信し、Cloud Schedulerのリトライや多重起動で二重送信しない。
- `NOTIF-009` LINEのchannel secret、channel access token、通知用DB接続文字列はSecret Managerで管理し、コード、Git、ログ、クライアントへ出さない。LINEのgroupIdもログ・画面へ出さない。
- `NOTIF-010` 必要な環境変数が未設定の場合、通知機能は安全に無効となり（fail closed）、Webhook・ジョブの各エンドポイントは処理を行わず404を返す。

### エクスポート

- `EXP-001` アクティブメンバーは、選択中グループで閲覧可能な取引をUTF-8 CSVとして出力できる。
- `EXP-002` CSVは列を明示し、招待情報や監査上の秘密情報を含めない。
- `EXP-004` 自動インフラバックアップはMVP対象外とする。

## 6. プライバシー方針

非公開取引は最初のMVPに含めない。グループ内の取引は、すべてのアクティブメンバーから閲覧できる。「自分の履歴」は表示上の絞り込みであり、他メンバーから隠す機能ではない。

理由は、一部の支出を隠しながらグループ合計を表示すると、合計値の意味が曖昧または誤解を招くためである。将来非公開記録が必要になった場合、共有グループ内の非公開行ではなく、個人グループとして扱うことを第一候補とする。

## 7. MVP対象外

- 削除した取引の復元・取り消し
- 銀行・クレジットカード連携
- レシートOCR・画像保存
- 振替・口座残高管理
- クレジットカードの締め日・支払日
- メンバー間の自動精算
- 固定費のjobによる自動登録（固定額月次の固定費設定は`REC-*`として実装済み）
- 予算警告の即時通知（月間予算・カテゴリ予算の設定と進捗表示は`BUD-*`、週次レポート内の予算進捗は`NOTIF-*`として実装）
- ブラウザのプッシュ通知（LINEへの週次レポートは`NOTIF-*`として実装）
- 完全なオフライン書き込み同期
- 自動バックアップ
- ネイティブアプリ
- 1グループ内の複数通貨
- 複数グループ横断集計
- 有料課金
- グループ削除

## 8. 非公開MVPの成功条件

- 2人のユーザーが1つのグループを作成・招待し、4週間継続利用できる。
- よくある支出を、ユーザビリティ確認で10秒以内に登録できる。
- 両ユーザーがグループ支出、自分の支出、自分の収入を区別できる。
- 自動セキュリティテストで、グループ間アクセスが1件も成功しない。
- 同じ期間・対象において、カレンダー合計と履歴合計が一致する。
