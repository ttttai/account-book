# 画面仕様

状態: 承認済み

バージョン: 0.3.9

## 1. モバイル基準

- 本アプリは主にスマートフォンから利用することを前提とする。すべての画面はモバイルファーストで設計し、デスクトップ表示は同じ情報設計を広い画面へ適応させる。
- 主要デザインviewportは375 x 812 CSS pixelとする。
- 最小対応コンテンツ幅は320 CSS pixelとする。
- 主要操作は精密なタップを必要とせず、44 x 44 CSS pixel以上のタップ領域を確保する。
- モバイルでは下部ナビゲーション、広い画面では適応型サイドナビゲーションを使う。
- PCの代表viewportは1280 x 800 CSS pixelとする。広い画面では本文・フォームの読みやすい最大幅を維持し、一覧と作成領域など同時に理解しやすい領域を2カラムへ配置できる。
- viewport幅を変えても横スクロール、要素の重なり、操作不能な領域を発生させず、情報の意味と操作順序を変えない。
- 金額は日本式の桁区切りと`¥`で表示する。カレンダーの日付セルも`10,000`のような10進数字を使い、`万`表記への省略や丸めを行わない。
- 色だけで意味を伝えない。

## 2. ナビゲーション

モバイル下部ナビゲーション:

```text
ホーム | 履歴 | 入力 | 分析 | 設定
```

下部ナビゲーションは選択中グループの画面で共通表示し、iPhoneのホームインジケーターとブラウザUIを考慮して`env(safe-area-inset-bottom)`を確保する。各項目は44 x 44 CSS pixel以上のタップ領域と文字labelを持ち、現在地は色だけでなく`aria-current`と視覚的な形状でも示す。「入力」は他項目と同じデザインで表示する。広い画面では同じ5項目・順序・意味を保ったサイドナビゲーションへ適応してよい。

「ホーム」は選択中グループの当月カレンダー、「履歴」は選択中グループの履歴、「入力」は選択中グループの取引入力、「分析」は選択中グループの概要分析、「設定」は選択中グループの設定ハブへ遷移する。ホームを押した場合は選択中グループの当月・グループ全体表示へ戻る。

共通ナビゲーションを表示する履歴、メンバー、カテゴリなどの画面では、headerに「ホーム」「グループ一覧」「ホームへ戻る」など同じ画面間移動を重複表示しない。headerはグループ名、画面名、画面固有の操作に限定する。履歴の絞り込み、メンバーの権限変更、カテゴリ操作など、機能固有の操作は共通ナビゲーションへ移さない。

アプリのコンパクトなheaderに選択中グループを表示する。グループの切り替え・作成は設定から行い、切り替えると切替先グループのホームへ遷移する。切替先で無効になるメンバー絞り込みは引き継がない。

グループ画面の標準URL:

```text
/groups/{groupId}?month=YYYY-MM&scope=group|me|member:{memberId}
```

## 3. 認証画面

### ログイン

- Googleログインボタンだけを主要操作として表示する。
- Googleログインボタンは通常のHTTP navigationとしてOAuth開始Route Handlerへ遷移し、JavaScriptによるform拡張の有無にかかわらず同じ認証フローを開始する。
- `localhost`など公開サイトと異なるoriginからログインを始めた場合も、利用者に追加操作を求めず公開サイトoriginへ揃えてからGoogleへ遷移する。
- Googleへの認可要求には`prompt=select_account`を付け、ブラウザにGoogleアカウントが1件だけ残っていても毎回アカウント選択画面を表示する（`AUTH-006`）。ログイン画面には「別のGoogleアカウントで使う場合は、ログアウト後にもう一度Googleでログインし、アカウントを選び直す」旨の短い補足を表示する。
- メールアドレス、ID、パスワード、OTPの入力欄、新規登録リンク、パスワード再設定リンクは表示しない。Googleの初回ログインが登録を兼ねる。
- 「このアプリは現在、許可されたアカウントだけ利用できる」ことを、具体的な許可アドレスや件数を表示せず説明する。
- loading、OAuth失敗、許可対象外、rate limit、サービス停止状態を表示する。
- OAuthの環境設定または許可リストが不完全な場合、ボタンを無効化し、管理者向けに設定不足と分かる文言を表示する。
- 旧`/signup`、`/forgot-password`、`/account/update-password`は`/login`へ転送する。

### 起動導線

- `/`はサービス紹介とログイン導線を持つ未認証向け画面とし、ホーム画面インストール版の`start_url`もこの画面を指す。
- 認証済みで`/`を開いた場合は紹介画面を表示せずホームへ遷移し、ログイン操作を求めない。ホーム（`/app`）は、起動時に開くグループが設定されアクティブに所属していればそのグループへ（`GRP-012`）、未設定でアクティブな所属グループが1件だけであればそのグループへ（`GRP-011`）、グループ一覧を表示せず当月カレンダーへ遷移する。
- 認証済みでログイン画面またはOAuth開始Routeへ到達した場合も、Google認証を再実行せずホームまたは検証済みの戻り先へ遷移する。
- 認証済みの起動では、ホーム（`/app`）のroute-level loadingを先に表示し、プロフィール・グループ一覧の取得完了まで全面が白いままの状態を作らない。cold startやProxyのsession確認そのものの待ち時間は本仕様の対象外とし、サーバーが応答を返し始めた時点から即時にskeletonを描画する。

### 認証済み共通操作

- 保護画面のheaderまたはプロフィールメニューからログアウトできる。
- ログアウト中は操作を無効化し、失敗時は再試行できる。
- プロフィール画面またはグループ未所属状態で現在の表示名を確認・更新できる。

## 4. グループ選択・作成

### グループ未所属状態

アクティブな所属がないログインユーザーへ表示する。

操作:

- グループを作成する
- 招待を承認する

### グループ選択

- アクティブな所属グループを一覧表示する。
- 内部権限IDではなく、ユーザー向けの権限名を表示する。
- 「グループを作成」を表示する。
- 選択中グループを明示する。
- アクティブな所属が1件だけの場合、`/app`はこの画面を表示せず、そのグループの当月・グループ全体のカレンダーへ遷移する。所属が0件は「グループ未所属状態」、2件以上はこの一覧を表示する。
- 設定の「グループを切り替える・作る」や履歴の「グループ一覧」など、一覧を明示的に開く導線は`/app?view=groups`とし、所属が1件でも一覧・プロフィール・グループ作成を表示する。`view=groups`以外の値は無視して既定の判定に従う。
- 起動時に開くグループ（`GRP-012`）が設定されアクティブに所属している場合、`/app`は所属件数にかかわらずそのグループの当月・グループ全体のカレンダーへ遷移する。一覧では該当グループの行に「起動時に開く」の表示を付け、他の行には付けない。設定先の所属を失っている場合は所属件数による判定へ戻る。

### loading

- プロフィールとグループ一覧の取得中は、header、プロフィール欄、グループカード形状のskeletonを`aria-busy`付きで表示する。
- skeletonは確定後の画面と同じshell（`protected-shell groups-overview`）を使い、375pxの縦配置と1280pxの2カラム配置を変えない。
- skeletonへ操作可能なボタン・リンクを置かない。

### エラー

- プロフィール・グループ一覧の取得がバックエンドの応答不能（接続失敗、timeout、5xx）で失敗した場合、ログイン画面へ遷移せず、同じshell（`protected-shell groups-overview`）で「ホームを読み込めませんでした」と「再試行」を表示する（`AC-AUTH-004-4`）。
- sessionが存在しない、無効、または期限切れで更新できない場合だけログイン画面へ遷移する。エラー表示にtokenや内部エラーの詳細を含めない。
- ホームとグループ配下以外の画面（招待の承認など）で同じ失敗が起きた場合は、ルートのerror境界が認証画面と同じカード形状で「読み込めませんでした」と「再試行」を表示する。

### グループ作成

MVP入力項目:

- グループ名: 必須、1〜50文字
- 週の開始曜日: 日曜または月曜
- 標準の支出負担方法: 均等または自分

通貨とタイムゾーンはJPY、Asia/Tokyoを標準設定し、詳細設定へ表示する。

## 5. ホームカレンダー

上から次の順に配置する。

1. 選択中グループ名を示すコンパクトなheader
2. 前月、選択月、翌月
3. 集計対象切替
4. 選択対象の月間合計（支出・収入・収支）
5. カレンダー
6. 共通下部ナビゲーション

通常の文字サイズにおける375 x 812 CSS pixelでは、header、月移動、集計対象、月間合計、曜日、42日分のカレンダー、下部ナビゲーションを初期viewport内へ収め、ページ全体の縦スクロールなしで月を把握できるようにする。カレンダー行は、`100dvh`からheader、集計領域、下部ナビゲーション、safe areaを除いた高さを6行で分ける。特定のiPhone機種寸法をコードへ固定せず、320px、375 x 667、375 x 812、390px、430pxおよび1280 x 800のviewportで適応させる。

高さが小さい画面または利用者が文字を大きくして内容が収まらない場合は、文字の切り捨てや操作の重なりを起こさず縦スクロールへ安全に切り替える。初期viewportへ収めるために日付、正確な金額、主要操作を欠落させてはならない。日付を選択した後の日別取引はbottom sheet相当で重ね、ホーム本文を縦長にしない。

### 月移動と今日へ戻る

- 月移動行は「前月」「選択月」「翌月」に加え、表示月が当月でないときだけ「今日」ボタンを表示する。選択月の年月は「今日」の表示有無にかかわらず画面の水平中央に固定し、左右の操作領域は対称に配置する。「今日」は現在の`scope`・`member`を維持してグループのタイムゾーン上の当月へ移動し、`day`は付けない。下部ナビゲーションの「ホーム」（当月・`scope=group`へ戻る）と役割を分ける。
- 当月表示中は「今日」を表示しないが、同じ寸法の不可視の領域を確保し、ボタンの有無で月移動行の高さ、集計領域、カレンダー行の高さ、日番号の位置を変えない。ボタンは44 x 44 CSS pixel以上、文字label「今日」を持ち、`aria-label`に移動先の月を含める。当月の判定はサーバーがグループのタイムゾーンで決めた値を使う。
- 月移動は「前月」「翌月」ボタンと「今日」ボタンだけで行う。カレンダー本体（曜日見出しと42セル）の横方向のスワイプ・マウスドラッグでは月を移動せず、横方向のpointer操作は日付セルのタップ、縦スクロール、ブラウザの戻る・進むジェスチャーの既定動作に委ねる。移動中の表示は「loading・エラー」の月移動と同じとする。

### 集計対象切替

概要分析と同じく、自分以外のアクティブメンバー数で枠を切り替える（`AC-CAL-004-1`・`AC-CAL-004-2`）。

- 0人（自分だけ）: 「グループ」「自分」の2枠。
- 1人（2人グループ）: 「グループ」「自分」「相手の表示名」の3枠。相手の枠は直接リンクとする。
- 2人以上: 「グループ」「自分」「メンバー」の3枠。3枠目は自分以外のアクティブメンバーだけを候補とする選択欄とする。

枠は1行で折り返さず、タップ領域は44px以上を保つ。2枠のときは等幅とする。3枠のときは「グループ」「自分」の文字を省略せず、余った幅は3枠へ均等に配分し、幅が足りないときは3枠目（相手の表示名または選択欄）だけを縮めて末尾を省略する。3枠目は320pxでも「グループ」枠以上の幅を持ち、省略しても高さを変えず、accessibility nameには表示名の全文を残す（`AC-CAL-004-3`）。選択欄の枠には開閉を示す印を表示し、印はCSSで描いてaccessibility nameへ含めない。選択欄の候補名は折り返して読み取れ、候補が多いときは一覧内を縦scrollできる。メンバー選択は利用者が開いたときだけ展開し、同じメンバーの再選択も含めて選んだ後は閉じ、カレンダーを覆わない。選択中はメンバー名を選択欄へ表示し、再度開けば別のメンバーへ切り替えられる。選択中の枠・候補には`aria-current="page"`を付け、自分のmembershipを`scope=member`で指定したURLでは「自分」枠を選択状態とする。対象切替では月を維持し、`day`を解除する。グループ・自分への切替では`member`を付けない。

「〇〇の支出」は対象メンバーの負担額合計を意味し、立て替えた支払額ではない。収入は、グループでは全収入、自分・メンバーでは対象メンバーが受取者の収入を集計し、支出と合算しない。

選択状態はURLの`scope=group|self|member`へ保存し、`scope=member`では`member=<membership UUID>`も必須とする。標準は`scope=group`とする。集計領域の支出側は対象メンバーが実際に負担した額で統一し、支払額は表示しない。

月間合計エリアは、主指標である支出合計（グループでは「グループ支出」、自分・メンバーでは「〇〇の支出」）を大きく示し、その横へ次を小さく並べる。ラベルは集計対象によらず「支出」「収入」「収支」の3語で統一し、「利用額」「受取額」のような別語を使わない。

- 収入合計: すべての集計対象で「収入」と明記し、`＋`つきで表示する（自分・メンバーでは対象メンバーが受取者の収入）。
- 収支差額（収入 − 支出）: 「収支」と明記し、黒字は`＋`、赤字は`−`、0円は`±`を金額の前へ表示する。色は補助とし、符号と数字だけで黒字・赤字が判別できるようにする。

収入・支出のいずれかが0円でも各値を省略せず表示する（両方0円のときは収支を`±￥0`とする）。集計領域の行数を増やす場合も、375 x 812で42日分のカレンダーと下部ナビゲーションが初期viewport内へ収まる制約を満たす。

### カレンダーの日付セル

行高と金額の大きさ（`AC-CAL-001-20`）:

- カレンダーの表は、ホーム本文からheader・月移動・集計対象・月間合計・下部ナビゲーション前の余白を除いた残り高さを受け取り、曜日見出しを固定の高さにして6行へ均等に配分する。行高に固定の上限を設けず、375 x 812では表の下に大きな空白を残さない（表の下端から下部ナビゲーション上端までは32px以内）。1280 x 800でも同じ規則で残り高さを使う。
- 各行の下限は44pxとする。日番号と支出・収入の両方を含む行が下限を超える場合はその行だけを広げ、下限でも収まらない高さでは縦スクロールへ切り替える。特定機種の寸法や行高の固定値をコードへ置かない。
- 日別金額の文字サイズは表の幅から算出し、`+999,999`が最小対応幅320pxのセルにも1行で収まる比率を基準にする。375px幅で11px以上、1280 x 800で16px以上とし、下限は0.5rem、上限は1.125remとする。日番号・曜日見出し・月間合計の文字サイズは変えない。

表示内容:

- 日番号
- 0円でない場合の正確な支出額
- 0円でない場合の正確な収入額（「＋」表記と収入用の色で支出と区別し、色だけに依存しない。桁区切り・折り返しの規則は支出額と同じ）
- 今日の表示
- 選択日の表示
- 曜日の表示（土曜日は薄い青、日曜日は薄い赤）

今日の表示と選択日の表示は、日番号と金額の配置を変えずに施す。強調の有無で日番号や金額の縦位置・行の高さが変わってはならず、同じ行の他セルと日番号の基準位置を揃える。

曜日見出しと日付セルはグループの週開始曜日に従い、表示月を常に6週・42セルで構成する。日番号は、実際の曜日に基づいて土曜日を薄い青、日曜日を薄い赤で表示する。色を変えるのは日番号だけとし、曜日見出しの文字色、セル背景、金額の色（支出はアクセント色、収入は収入用の色）は曜日で変えない。色は曜日見出しの文字による識別の補助であり、今日の塗りつぶしは土日でも維持する。選択月以外の日付は視覚的に弱く表示し（土日は弱い表示のまま色相だけ区別する）、金額を表示せず選択操作も提供しない。日付をタップすると、カレンダー本体を待機表示へ置き換えず選択状態と日別取引を即時に更新し、`day=YYYY-MM-DD`をURLへ保存する。モバイルではbottom sheet相当、広い画面ではside panelとして日別取引を表示する。

初回表示・再読み込みではserverが`day`を検証する。hydration後に同じ月・scope・member内で日付を選択または解除する場合は、認可済みの月間queryが作成した日付別の最小DTOをClient Componentが表示にだけ利用し、月間query、認証・所属確認、月間集計を再実行しない。Client Componentは金額を再計算せず、DB行を直接受け取らない。URLはNative History APIで更新し、ブラウザの戻る／進むでも選択日と日別パネルを同期する。

セルの表示額は金額の大小にかかわらず、桁区切りした正確な10進数字とする。`万`表記への省略や丸めは行わない。通常の文字サイズでは6桁以下の金額（999,999円以下）は、収入の「+」を含めて最小対応幅320pxのセルでも折り返さず1行で表示する。7桁以上の金額は、セル幅に収まらない場合だけ桁区切り記号の直後で折り返してよい。いずれの場合も`12,80`と`0`のようにけたの途中で分断して表示せず、数値を欠落させない。accessibility textには正確な日付とJPY金額を含める。カレンダーのJPY金額文字列は、実行環境のlocale実装に依存しない決定的なフォーマットで生成し、server renderとclient hydrationで同一のmarkupになることを保証する。通貨記号は`￥`（全角）で統一する。

### 日別取引sheet

固定費の行は、カテゴリ・固定費ラベル・金額の直下に登録した名称を独立した行で全文表示する（`AC-CAL-005-2`）。支出・収入の両方に適用し、名称は強調して長い連続文字列も折り返す。名称のない場合は空の行を作らない。名称とメモはHTMLとして解釈しない。

各取引にはメモがある場合、受取者（収入）と内訳（支出）の下にメモ全文を表示する（`AC-CAL-005-1`）。単発と定期の支出・収入に適用し、空白のみ・未記入の欄は省く。改行を保持して長い連続文字列も折り返す。HTMLとして解釈せずテキスト表示する。認可済みの月間データから最小DTOへ渡し、日付選択では再取得しない。

- 正確な日付と日別合計
- 同じ取引日内では、作成日時の新しい順に表示
- 金額、カテゴリ、内訳（支出）または受取者（収入）。支出の支払者は表示しない（`TXN-018`）
- 権限に応じた編集・削除操作
- 日付を初期入力した取引追加

日別取引sheetは支出と収入を作成日時の新しい順に表示する。`scope=self|member`では、支出行へ取引金額とあわせて対象メンバーの負担額を「〇〇の支出」として示す。収入は「＋」表記と収入用の色・受取者表示で支出と区別し、内訳と対象者の支出額を表示しない。支出行の負担内訳は「内訳」と表記し、支払者を表示しない（`AC-TXN-018-3`）。カテゴリ、受取者、内訳はDB行を直接渡さず、サーバーqueryが表示用DTOへ変換する。

各取引行のカテゴリは、履歴・取引入力・カテゴリ管理と同じ色ドットとカテゴリ名を並べて表示する（`AC-CAL-001-18`）。色は補助情報とし、カテゴリ名を常に表示して色だけで意味を伝えない。色はカテゴリ管理の定義済み18色token（`AC-CAT-002-7`）だけを`data-category-color`属性と共通design token（`src/app/styles.css`の属性selectorが設定する`--category-color`）で描画し、サーバーqueryがDBの色文字列を許可済みtokenへ正規化してDTOへ入れる。未定義・許可外の色は既定色（「その他」と同じ）へ寄せ、任意の色文字列をinline styleやclass名へ組み込まない。固定費の展開行にも同じ規則を適用する。

### loading・エラー

- 月移動時は全面を空にせず、カレンダー形状のskeletonを表示する。
- 同じ月・scope・member内の日付切替ではroute-level skeletonを表示しない。
- 取引がない月でもカレンダーを維持し、短い空状態メッセージを表示する。
- 月データの取得に失敗した場合、選択月を維持したまま再試行を表示する。
- Supabase Auth・PostgRESTが応答しない、または5xxを返す場合はログイン画面へ遷移せず、「カレンダーを読み込めませんでした」と再試行を表示する。sessionが存在しない、無効、または期限切れで更新できない場合だけログイン画面へ遷移する（`AC-AUTH-004-4`）。
- `month`、`scope`、`member`、`day`が不正な場合は値を暗黙補正せず、取引情報を含まない検証エラーと当月へ戻る操作を表示する。

## 6. 取引入力

モバイルでは全画面sheetとして開き、直接URLで開いた場合は専用routeとして表示できるようにする。

画面は上から種別、金額、詳細（取引日、収入の受取者、分け方、内訳の確認、メモ）の順に並べ、カテゴリ選択・テンキー・保存を画面下部の入力ドックへ固定する。金額の入力中もカテゴリと保存が隠れないようにし、OSの仮想キーボードを開かずに金額を入力する。

入力順:

1. 種別: 支出または収入
2. 金額: 画面内のテンキー (TXN-014)
3. カテゴリ: 入力ドックの1行表示、または「すべて」で展開した一覧から選ぶ (TXN-015)
4. 取引日: グループのタイムゾーンにおける今日を初期値とする
5. 収入の場合は受取者。支出の支払者は表示せず、現在のメンバーを隠しfieldで送信する (TXN-018)
6. 支出の場合は分け方: 1人、均等、カスタムの順に表示し、初期選択は1人。「1人」では「支出した人」を選ぶ
7. メモ
8. 保存

動作:

- カテゴリは、名称が常時見える選択肢として表示する。既定は入力ドック内の横1行とし、「すべて」で展開したときは2列に配置する。各選択肢の全体を44 x 44 CSS pixel以上のタップ領域とし、選択状態を枠・背景・選択記号で示す。カテゴリ色は補助情報として扱い、名称と選択記号を省略しない。
- カテゴリ選択はHTMLのradio semanticsを維持し、キーボードfocusを視認できるようにする。320pxでも名称の欠落、横スクロール、操作の重なりを発生させない。
- 支払者の入力欄を表示せず、端末上で最後に使った支払者を記憶しない (AC-TXN-018-2)。
- 収入の場合は分け方・内訳の入力を隠し、受取者を必須にする。
- 保存前に計算済みの内訳を「内訳の確認」として表示する。文言に「負担」「支払者」を使わない (AC-TXN-018-2)。
- 入力ドック（カテゴリ、テンキー、保存）を画面下部へ固定し、フォームの長さやscroll位置にかかわらず保存を常に押せる状態にする。固定した入力ドックと画面下部ナビゲーションの間に隙間を作らず、その領域から背後のフォーム内容が見えないようにする。固定を解除して静止したときも、ドックの背景をカードの外へはみ出させない。
- 送信中は二重送信を無効化する。
- 結果不明の再送時は、同じ`client_request_id`を再利用する。
- 編集競合時は、他の更新があったことを説明し、再読み込みを案内する。

### 金額のテンキーとカテゴリの入力ドック

- 金額はOSの仮想キーボードに依存せず、画面内のテンキーで入力する (TXN-014)。金額欄は`inputmode="none"`とし、物理キーボードからの入力とスクリーンリーダーからの読み上げ・編集は維持する。
- テンキーは1〜9、0、00、1文字削除に加え、四則演算の÷、×、−、+と=を備える (TXN-017)。数字は3列、演算子はその右の1列に上から÷、×、−、+の順で置き、1文字削除・=・保存は右端の列へ上から順に置く。テンキーの「閉じる」は数字配列には混ぜず、入力ドックの右上へ置く (TXN-014)。各キーは44 x 44 CSS pixel以上とし、ドック下端は画面下部ナビゲーションとsafe areaを確保する。
- 金額欄は電卓の表示部として働く。演算子を押すと金額欄へ「1,200+」のように式を続けて表示し、右辺の入力中は保存時に使う計算結果を金額欄の直下へ「= ¥1,500」と示す。式に含める演算子は1つまでとし、右辺がある状態で別の演算子を押すと計算して結果を左辺にする。=は式を計算結果だけの表示へ戻す。保存は=を押していなくても計算結果を送信する (TXN-017)。
- 金額欄は入力中も他の画面（§1の金額表記、カレンダー、履歴、分析、内訳の確認）と同じ3桁区切りで表示する（`¥128,000`）。式では左辺・右辺の各項を区切り（`1,200+300`）、直下の「= ¥1,500」と表記をそろえる。桁区切りは表示だけの加工とし、フォームが送信する金額と式の状態は区切りなしの整数のままにする。物理キーボードや貼り付けで入った`,`は無視し、区切りの位置に関係なく数字と演算子だけを式へ反映する。区切り記号の表示はlocale実装に依存しない決定的な整形で行い、スクリーンリーダーには区切り込みの値をそのまま読ませる (AC-TXN-014-10)。
- 計算は整数のJPYで行い、÷の端数は四捨五入する。0円未満または上限超過になる式は計算せず、理由（「0円未満にはできません」など）を金額欄の直下へ示して送信する金額を空にする。右辺にも先頭0の禁止を適用するため、0で割る式は組み立てられない。物理キーボードの`+`、`-`、`*`、`/`は同じ演算子として扱う。
- 保存は入力ドック内へ常設し、テンキーの開閉とカテゴリの展開のどの状態でも押せる。数字キーと1文字削除（および右上の「閉じる」）だけを開閉の対象とし、開いている間は保存を数字キーの右列（1文字削除の下）へ、閉じている間は全幅へ置く。保存行を追加してドックを高くしない (TXN-016)。
- テンキーは金額欄を選んだときに開き、金額欄以外の入力欄（取引日、受取者、分け方、内訳、メモ）を選んだとき、またはテンキー内の「閉じる」キーを押したときに閉じる。「閉じる」以外のドック内のカテゴリ・キー・保存の操作では開閉しない (TXN-014)。
- 「閉じる」は、金額を入力し終えて下部のフォームを広く見たいときの明示的な閉じ方として、入力ドックの右上（「カテゴリ」見出し行の右端、「すべて」の真上）に置く。OSの仮想キーボードの「完了」と同じ位置感にし、テンキーの行や数字配列は変えない。テンキーを開いている間だけ表示し、見出し行はその高さ（44 x 44 CSS pixel以上のタップ領域）に合わせて広げ、カテゴリ行と重ねない。押しても入力済みの金額・式は残り、閉じた直後のfocusは金額欄へ置く（このfocus移動ではテンキーを開かない）。文言は「閉じる」とし、スクリーンリーダーには「テンキーを閉じる」と伝える。見た目はカレンダー日別パネルの「閉じる」と同じ枠なしのテキスト（控えめな色）にし、「すべて」やテンキーのキーより目立たせない。900px以上では入力ドックを固定せずテンキーがフォームを覆わないため、「すべて」と同様に表示しない。
- テンキーを閉じている間は、金額欄をタップすると再び開くことを金額欄の近くへ短く示す。閉じている間もOSの仮想キーボードは開かず、物理キーボードとスクリーンリーダーからの入力・読み上げは維持する。
- テンキーを開くと入力ドックが高くなるため、金額欄がドックへ隠れない位置まで表示位置を移動する。式の計算結果や理由の行が現れたときも同じく隠れない位置へ移動する。桁区切り記号を含めて8文字以上になる式や金額（`1,234,567`、`1,200+30`など）は金額欄の文字を小さくし、幅を超えた場合は末尾が見えるように表示位置を寄せる (TXN-017, AC-TXN-014-10)。
- 金額は先頭に0を作らず、`9,007,199,254,740,991`円を超える桁を追加しない。上限や不正な入力は無視し、入力済みの値を壊さない。
- カテゴリは既定でドック内の横1行に表示し、横scrollで全件へ到達できる。選択中のカテゴリは選択記号と背景で常に判別できるようにする。
- 行には常時見える「すべて」を置き、押すと全カテゴリを2列で展開する。展開中はテンキーを隠し、「閉じる」または任意のカテゴリ選択で元の1行へ戻す。展開はボタン操作で行い、スワイプだけでしか到達できない操作にしない。
- 展開・折りたたみでカテゴリのradio semanticsと選択状態、フォームの他の入力値を保持する。展開状態は`aria-expanded`で伝える。
- カテゴリが増えても1行の高さを増やさず、320pxでカテゴリ名の欠落、ページ全体の横scroll、キーの重なりを発生させない。
- 900px以上では入力ドックを画面下部へ固定せず、静的に配置してカテゴリを常に2列で表示する。

取引入力は`/groups/{groupId}/transactions/new`を直接開ける専用routeとして提供し、グループホームの主要操作から遷移する。種別は画面上部の切替（支出・収入）で選び、初期選択は支出とする。切替は支出と収入の2つの選択肢だけを等幅で並べ、分け方（1人・均等・カスタム）の3列と列数を共有せず、空の選択枠を表示しない (AC-TXN-013-7)。

収入を選択した場合:

- カテゴリ選択肢を収入カテゴリ（未アーカイブ）へ切り替える。アクティブな収入カテゴリがない場合は保存できないことを説明する。
- 「受け取った人」をアクティブメンバーから必須で選択する。初期選択は現在のメンバーとする。
- 分け方・内訳プレビューを表示しない。収入に負担額は設定しない (TXN-013)。
- 保存の冪等性（`client_request_id`）、二重送信防止、保存後の遷移は支出と同じとする。
- 収入は履歴とCSVへ表示し、ホームカレンダーの支出集計へは含めない (CAL-009)。日別取引sheetには支出と区別して表示する。

- 金額欄は`inputmode="numeric"`とし、円単位の整数を入力する。
- 支払者は画面に表示せず、登録時は現在のメンバーを隠しfieldで送信する。Server Actionの支払者検証は変更しない (AC-TXN-018-1)。
- 分け方の初期選択は常に「1人」とし、現在のメンバーを「支出した人」に選択する。「均等」へ切り替えた場合は全アクティブメンバーを選択する（ユーザーが複数選択を調整済みの場合は維持する）。グループの標準負担方法は初期選択に使用せず、グループ属性として保持する。
- 均等・1人・カスタムを切り替えても、保存前にメンバー別の確定した内訳と合計を常に表示する。
- 入力不備は該当欄の近くへ表示し、認証切れ・権限不足・通信失敗はフォーム全体のエラーとして表示する。失敗時に入力値と`client_request_id`を維持する。
- 保存中は主要ボタンを無効化し、成功時は対象グループのホームへ戻る。

### 取引編集

取引編集の標準URLは`/groups/{groupId}/transactions/{transactionId}/edit`とし、日別取引sheetと履歴の取引行から遷移する。アクティブメンバーだけが開ける。削除済み・存在しない・別グループの取引はNOT_FOUND相当として安全に拒否し、取引情報を返さない。

- 支出登録と同じフォーム構成・検証・タップ領域を使い、保存済みの金額、取引日、カテゴリ、内訳、メモを初期表示する。支払者は表示せず、保存済みの支払者を隠しfieldで送信する (AC-TXN-018-1)。
- 保存済みの内訳から分け方を決定的に復元する。負担行が1件で全額なら「1人」、負担行が同じメンバー選択に対する均等配分結果と一致するなら「均等」、それ以外は「カスタム」として表示する。
- サーバーqueryが返す現在の`version`を隠しfieldで保持し、保存時に`expectedVersion`として送信する。競合時は他の更新があったことを説明し、再読み込みを案内する（入力値は維持する）。
- 取引のカテゴリがアーカイブ済みの場合、現在のカテゴリを「（アーカイブ済み）」として選択肢に含め、変更せずに保存できる。変更する場合はアクティブな支出カテゴリだけを選べる。
- 支出した人（負担者）は常にアクティブメンバーから選択する。保存済みの負担者が削除済みメンバーの場合は、アクティブメンバーだけで内訳を設定し直さなければ保存できないことを入力欄の近くで説明する。保存済みの支払者が削除済みメンバーの場合は現在のメンバーへ自動で置き換えて送信し、画面では説明しない (AC-TXN-018-1)。
- 収入の編集では受取者と収入カテゴリを同じ規則で扱い（受取者はアクティブメンバー必須、削除済み受取者は変更を要求、アーカイブ済みカテゴリは変更しない場合のみ維持可能）、分け方・内訳プレビューを表示しない。
- 取引の種別（支出・収入）は編集で変更できず、種別切替を表示しない。
- 保存成功時は遷移元（日別取引sheetまたは履歴）へ戻る。戻り先が検証できない場合はグループホームへ戻る。

### 取引削除

- 削除操作は編集画面に文字labelつきで表示し、実行前に対象の金額・日付と「削除した取引は元に戻せない」ことを確認dialogで示す。
- 削除要求には現在の`version`を使い、競合時は他の更新があったことを説明する。すでに削除済みの取引への削除の再送は、状態を変更せず成功として扱う。
- 削除成功時は遷移元へ戻り、カレンダー・履歴の合計から即時に除外して表示する。
- 削除操作は入力フォームの後ろに置くが、固定入力ドックの高さぶんの余白はフォーム内だけでなく削除操作を含む領域全体へ確保し、最下部までscrollすれば削除操作と確認dialogがドック・下部ナビゲーションに覆われずタップできる (AC-TXN-009-5)。

## 7. 履歴

- 取引日の新しい順に表示する。
- 月を選択できる。
- 種別、カテゴリ、受取者、支出した人（`member`）の絞り込みsheetを表示する。支払者（`payer`）の選択肢と適用中条件は表示しない。URLで渡された`payer`の検証と適用は維持する (AC-HIS-002-1)。
- shortcut chipは`自分の支出`だけを表示し、現在メンバーの`member`絞り込みを切り替える。他条件を維持しcursorを解除する。`自分の利用`・`自分が支払った`・`自分が負担`chipは表示しない。支出した人はsheetでも選択できる。shortcutによる切り替え後はsheetの選択値も適用中条件へ同期する。
- 支出した人の選択時は適用中条件へ「支出した人 〇〇」を表示し、支出行の主金額に対象者の負担額と「〇〇の支出」ラベルを表示し、「取引全体」の金額を補足する。未選択時と収入の表示金額は従来どおり。認可済みサーバー処理で負担額をDTOへ設定し、追加ページも同じ規則を使う。
- 各行には支出の支払者を表示せず、支出した人（負担メンバー）と収入の受取者を表示する。支出は「山田」、2人以上へ配分された支出は「山田・佐藤」と表示名だけを列挙し、「支出した人」の見出し語、各人の金額、人数だけの要約（「2人で分割」）は表示しない。「負担」「支払者」の語は使わない (AC-TXN-018-3、AC-HIS-006-2、AC-HIS-007-1)。
- cursor方式の「さらに読み込む」を使用する。
- 適用中の絞り込み条件を表示し、個別に解除できる。
- 空状態・エラー状態でも現在の絞り込みを維持する。
- 過去取引に登場する削除済みメンバーは、履歴絞り込み上で履歴用表示名として選択可能にする。

### 一覧の行構成（HIS-006）

- 取引は取引日ごとの日付見出しで束ねる。見出しは当年なら「9月8日（火）」、他年なら「2025年12月31日（水）」とし、曜日はサーバーが返す取引日から純関数で求める。見出しの下の行には日付を繰り返さない。「さらに読み込む」で同じ日付の行が続く場合は見出しを重複させず、既存の日付グループの末尾へ追記する (AC-HIS-006-1)。
- 1取引は1〜2行構成とする。1行目はカテゴリ色の印、カテゴリ名、金額。2行目はメモと、支出なら支出した人の表示名（「山田」「山田・佐藤」）、収入なら「受取者 〇〇」を小さく表示する。メモが無い行は2行目を表示名・受取者だけにする。収入は金額の前に「収入」の印を置く。メモと表示名が同じ行にあるときは、表示名を行幅の7割を上限に省略記号で切り、メモを残り幅で縮める。メモが無ければ表示名が行幅全体を使う (AC-HIS-007-1、AC-HIS-007-3)。
- member指定時の支出は主金額を対象者の負担額とし、金額の下に「取引全体 ￥6,000」を小さく補足する。主金額のラベル「〇〇の支出」は行の中では表示せずアクセシブル名に含める。適用中条件の「支出した人 〇〇」で対象を示す (AC-HIS-003-3、AC-HIS-006-4)。
- 行全体を取引編集へのリンク（`/groups/{groupId}/transactions/{transactionId}/edit?from=...`）とし、行内に全幅の「編集」ボタンを置かない。リンクのアクセシブル名は「日付 カテゴリ名 金額」を基本とし、member指定時は「〇〇の支出 金額 取引全体 金額」、続けて支出なら支出した人の表示名（「山田・佐藤」）、収入なら「受取者 〇〇」、メモがあれば末尾にメモを含める。「支出した人」の語は絞り込みsheetのラベルと重なるため行のアクセシブル名へ入れない (AC-HIS-007-2)。行の高さは44 CSS pixel以上、focus時は枠線で位置を示し、Enterで遷移する (AC-HIS-006-3)。
- 375 x 812の初期viewportに8件以上の行が入ることを目標とし、行のpaddingは上下0.55rem程度、行間の罫線は日付グループ内の区切り線だけとする。ページ見出しはホーム・分析と同じ1行の見出し（eyebrowとグループ名を横並び）とし、見出しから最初のchipまでの空きを他画面と同じ程度にそろえる (AC-HIS-006-4)。
- 1280 x 800では絞り込みを左、一覧を右に置く2カラムを維持し、行構成は375pxと同じにする。

履歴の標準URLは`/groups/{groupId}/history`とし、絞り込み条件とcursorはURL search paramsへ保存してサーバーで検証する。再読み込み・URL共有で同じ絞り込みを復元する。「さらに読み込む」は表示済みの行を維持したまま続きを追記し、読み込み中も表示済みの行と適用中の絞り込み表示を消さない。グループホームから履歴への導線を表示する。

## 8. メンバー

- アクティブメンバー一覧
- 権限名
- owner/admin向け招待ボタン
- owner向け権限変更・削除操作
- owner/admin向け保留中招待一覧
- 作成直後の招待リンクコピー

招待作成では追加後の権限を「管理者」「メンバー」から選ぶ。標準は「メンバー」とし、ownerは選択肢に含めない。有効期限は作成時刻から72時間で固定し、保留中一覧へ期限を表示する。owner/adminは保留中招待を取り消せる。

共有リンクは`/invitations/accept#token=...`形式とする。承認画面はURL fragmentまたは同一tabの`sessionStorage`からトークンを読み、トークン値自体を画面へ表示しない。未認証時はGoogleログインへの導線、認証済みでは参加確認ボタンを表示する。無効な形式、期限切れ、取消済み、使用済み、許可対象外を安全なメッセージで表示し、グループの存在や内部token hashを公開しない。

生の招待トークンを含むリンクは作成直後だけ表示する。確認画面を離れた後に再表示しない。

最後のownerには降格、削除、脱退操作を表示しない。別メンバーをownerへ昇格すると操作可能になる。

権限変更と削除の操作はownerにだけ表示し、実行前に対象メンバーと変更内容を確認できるようにする。削除は物理削除ではないことが誤解されない文言（例: 「グループから外す」）を使い、成功・失敗を画面へ表示する。削除済みメンバーはアクティブ一覧から除外し、過去取引の表示名は維持する。

- プロフィール表示名の確認・更新
- 起動時に開くグループの設定・解除
- グループ切り替え・作成
- メンバー一覧・招待・権限管理への入口
- グループ設定（グループ名、週の開始曜日、標準の分け方の確認・変更。通貨・タイムゾーンは表示のみ）
- カテゴリ管理への入口
- 固定費・予算への入口
- CSV出力の入口
- 所有権制約を満たす場合のグループ脱退
- ログアウト

グループ削除はMVPに表示しない。

アカウント項目の「起動時に開くグループ」は、表示中のグループが起動時に開くグループでなければ「このグループを起動時に開く」ボタンを、起動時に開くグループであれば「このグループを起動時に開きます」の状態表示と「解除する」ボタンを表示する。ボタンは44 x 44 CSS pixel以上とし、実行中は無効化して結果メッセージを同じ項目内へ表示する。設定はメンバー権限を問わず本人のアカウント設定として扱い、他のメンバーの起動時の遷移先へ影響しないことを補足文で示す。

「グループ設定」項目（`GRP-013`）は、owner/adminにはグループ名（1〜50文字のテキスト入力）、週の開始曜日（日曜日・月曜日）、標準の分け方（メンバーで均等・自分だけ）の編集フォームと「保存する」ボタンを表示する。ボタンは44 x 44 CSS pixel以上とし、保存中は無効化する。通貨（JPY）とタイムゾーン（Asia/Tokyo）は同じ項目内に読み取り専用で表示し、「通貨とタイムゾーンは現在JPY・日本時間（Asia/Tokyo）に固定で、変更できません」の補足文で変更手段が無い理由を示す。フォームは読み込み時の`version`を隠しfieldで保持し、保存結果（成功・入力エラー・競合・権限不足）を同じ項目内へ表示する。成功時は他画面へ遷移せず、画面見出しのグループ名と項目内の値を更新後の値にする。競合時は他のメンバーが先に変更した旨と再読み込みを案内し、入力中の値を破棄しない。memberには同じ項目をグループ名・通貨・タイムゾーン・週の開始・標準の分け方の読み取り専用一覧として表示し、編集操作を出さない。項目の文言は「分け方」を使い、「負担」を表示しない（`AC-TXN-018-2`）。

設定の標準URLは`/groups/{groupId}/settings`とし、設定ハブから権限に応じて各管理画面へ遷移する。メンバーとカテゴリの詳細画面は既存の専用routeを維持するが、共通ナビゲーションでは「設定」を現在地として示す。権限がない管理操作は入口を隠すか権限不足として安全に拒否し、設定ハブを認可の代替にしない。

### カテゴリ管理

カテゴリ管理の標準URLは`/groups/{groupId}/categories`とし、owner/adminだけが開ける。種別（支出・収入）ごとに並び順でアクティブカテゴリを一覧表示し、追加、名称変更、並び替え、アーカイブを提供する。各操作は44 x 44 CSS pixel以上のタップ領域を持ち、確認と結果（成功・検証エラー・権限不足）を画面へ表示する。アーカイブ済みカテゴリは通常一覧と新規取引の選択肢に表示しない。memberが直接URLを開いた場合は権限不足として拒否し、カテゴリデータを返さない。

一覧は1カテゴリ1行のコンパクト表示とし、各行に「ドラッグハンドル」「カテゴリ色」「名称」「編集」だけを置く。行とハンドル・編集の各操作は44 x 44 CSS pixel以上のタップ領域を持つ。

並び替えは次の2系統を提供する。

- ドラッグ並び替え: 各カテゴリ行に44 x 44 CSS pixel以上のドラッグハンドルを置き、pointer操作（タッチ・マウス共通）で任意の位置へ移動できる。ハンドルは`touch-action: none`としてドラッグ中の画面スクロールと衝突させず、一覧の他領域のスクロールは妨げない。ドラッグ中は対象行を持ち上げ表示し、挿入予定位置を視覚的に示す。ドロップで並び順を確定し、確定中は再操作を防ぐ。保存失敗時は元の順序へ戻し、エラーを表示する。
- キーボード並び替え: ドラッグハンドルはfocus可能とし、focus中の上下矢印キーで対象を1つ上・下へ移動できる。結果はメッセージ領域で通知する。「上へ」「下へ」ボタンは提供しない。

ドロップ・キー操作時にクライアントが送るのは対象カテゴリと移動先位置だけとし、新しい全体順序はサーバーが現在の並びから組み立てて検証する（AC-CAT-002-3の全体順序検証を経由する）。

編集は行の「編集」から行内に展開する編集パネルで行い、次を提供する。

- 名称の変更と色の変更を1つの保存操作で確定する。色は定義済みパレット（`AC-CAT-002-7`の18色トークン）から44 x 44 CSS pixel以上のswatchで選択し、選択状態を色以外（枠・記号）でも示す。swatchは幅に応じて折り返し、375pxでは4行以内、320pxでは5行以内で横scrollなしに全色を表示する。各swatchは色名（レッド、オレンジなど）をaccessibility labelと`title`に持ち、既定の9色を先、追加の9色を後に並べる。
- カテゴリ色のtokenと色値の対応は`src/app/styles.css`の`[data-category-color="<token>"]`が設定するCSS custom property `--category-color`として1箇所で定義する。各機能のCSS Modulesは自機能のドット・swatch・棒へ`background: var(--category-color, <既定色>)`を適用するだけとし、tokenごとの色値を再定義しない。
- カテゴリの「削除」。確認文（過去の取引の表示と集計は変わらないこと、新規入力の選択肢から外れること）を提示し、明示的な確認操作を経てから実行する。内部挙動は従来のアーカイブ（論理アーカイブ）のままとし、画面上の文言は「削除」で統一する。
- 編集パネルは同時に1行だけ開き、キャンセルで変更を破棄して閉じる。

支出・収入の初期カテゴリ作成や種別ごとの管理範囲は従来どおりとする。

## 10. 固定費

標準URLは`/groups/{groupId}/recurring-transactions`とし、設定ハブから遷移する。共通ナビゲーションの現在地は「設定」とする。閲覧はアクティブメンバー、作成・編集・終了はowner/adminに限る。

- 一覧は種別、名称、金額、毎月の日付、開始月、終了月を表示し、375 x 812では1件1カードの縦一覧とする。1280 x 800では一覧とフォームを2カラムへ適応させてよい。
- 終了済みの固定費は終了と分かる表示にし、一覧の末尾へ置く。
- 0件のときは登録できる内容が分かる空状態を表示する。memberには作成・編集・終了の操作を表示しない。
- 作成・編集の入力順は、種別、名称、金額、毎月の日付、開始月、終了月（任意）、カテゴリ、収入の受取者、支出の分け方、メモとする。支出の支払者は表示せず、作成時は現在のメンバー、編集時は保存済みの支払者（削除済みなら現在のメンバー）を隠しfieldで送信する (AC-TXN-018-1)。
- 保存前に「毎月○日に○円」と内訳を要約表示する。一覧のカードにも支出の支払者を表示しない (AC-TXN-018-3)。
- 金額は取引入力と同じ画面内テンキーで入力する（REC-010）。金額欄は`inputmode="none"`としてOSの仮想キーボードを開かず、¥表記の金額欄の直下へテンキー（1〜9、0、00、1文字削除）をフォーム内に静的に配置する。取引入力の固定ドックは持たず、下部ナビゲーションを覆わない。
- テンキーは金額欄を選んだときに開き、金額欄以外の入力欄を選んだときに閉じる。テンキー自体の操作では開閉と入力値を変えない。閉じている間は金額欄をタップすると再び開くことを金額欄の近くへ短く示し、物理キーボードとスクリーンリーダーからの入力・読み上げは開閉状態にかかわらず維持する。
- テンキーを開いたとき、キーが下部ナビゲーションへ隠れる場合は隠れない位置まで表示位置を移動する。各キーは375 x 812と320pxで44 x 44 CSS pixel以上とし、先頭0と安全な整数の上限は取引入力と同じ規則で扱う。
- 名称・メモなど文字入力欄はOSのキーボードを使う。
- 入力不備は該当欄の近く、権限不足・通信失敗はフォーム全体のエラーとして表示する。編集競合時は他の更新があったことを説明し再読み込みを案内する。
- ホームカレンダーでは展開された固定費を合計と日別取引sheetへ含め、日別取引sheetでは「固定費」と分かるlabelで単発取引と区別する。展開取引には編集・削除の操作を提供しない。

## 11. 概要分析

標準URLは`/groups/{groupId}/analytics?month=YYYY-MM&scope=group|self|member&member={membershipId}`とし、共通ナビゲーションの「分析」から1タップで開く。現在地は「分析」とする。閲覧はアクティブメンバーに限る。

375 x 812では次の順に縦配置し、支出・収入・収支を最初のスクロール前に確認できることを目標とする。

1. 選択月と前月・翌月操作（44 x 44 CSS pixel以上）
2. 集計対象（グループ・自分・メンバー）。ホームカレンダーと同じ意味・同じ並びとし、自分以外のアクティブメンバー数に応じて枠を切り替える
3. 支出・収入・収支の3指標。金額は`￥123,456`のように省略せず表示する
4. 前月との差額（符号付き）。前月に対する比率は表示しない
5. 予算値がある月だけ予算進捗（消化額・残額・消化率）
6. 支出のあるカテゴリ全件（金額の降順、丸めなし）の円グラフ（既定）と一覧。一覧は1カテゴリ1行で色の印・名称・金額・構成比を並べ、見出し横の切替で横棒グラフへ変更できる（`AC-ANA-004-1`、`AC-ANA-014-1`、`AC-ANA-014-4`）
7. ホームカレンダー・履歴への導線

- 横スクロール式のカード列を使わない。320px幅で横スクロールを発生させない。
- 集計対象は自分以外のアクティブメンバー数で表示を切り替え、枠を折り返さない。0人は「グループ」「自分」の2枠、1人は3枠目をそのメンバー名の直接リンク、2人以上は3枠目をホームカレンダーと同じメンバー選択欄とする。3枠の幅配分・省略・選択欄の開閉の印はホームカレンダーと同じ規則（`AC-CAL-004-3`）に従い、「グループ」「自分」を省略しない。
- 分析のメンバー選択欄の候補は自分以外のアクティブメンバーだけとし、「自分」枠と重複させない。利用者が開いたときだけ展開し、選んだ後は閉じた状態で選択中の表示名を枠へ表示する。候補が多い場合は選択欄の中だけを縦scrollさせ、page全体を横scrollさせない。
- 集計対象のリンクは`month`・`scope`・`member`をURLへ保持し、選択中の枠と候補を`aria-current`で示す。長い表示名は3枠目の残り幅を使ったうえで枠内で省略表示してよいが、候補一覧では全員へ到達できるようにする。
- 円グラフの扇形と横棒は装飾とし、一覧にカテゴリ名、色の印、正確な金額、構成比テキストを併記する。扇形の角度、棒の長さ、色だけで値を伝えない。切替ボタンは44 x 44 CSS pixel以上で`aria-pressed`を持ち、切替はページ遷移・再取得なしで即時に反映する（`AC-ANA-014-2`、`AC-ANA-014-3`）。
- 収支は符号（`＋`・`−`・`±`）で黒字・赤字・0円を示し、色だけに依存しない。
- 取引が0件の月は0円の指標と「この月の取引はまだありません。」を表示し、エラーとして扱わない。
- 月、集計対象、メンバーの指定が不正な場合は取引を読み込まず、当月・グループ表示へ戻る導線だけを表示する。
- 取得失敗時は前回値を最新値として表示せず、再試行操作を提供する。
- 1280 x 800では同じ情報構造と同じ値を保ったまま、指標とカテゴリ内訳を2カラムへ適応させてよい。

## 12. 詳細分析

標準URLは`/groups/{groupId}/analytics/details?start=YYYY-MM&end=YYYY-MM&scope=group|self|member&member={membershipId}`とする。概要分析の「詳しく見る」から選択月を終了月とする6か月表示を開く。共通ナビゲーションの現在地は「分析」のままとする。

375 x 812では次の順に縦配置する。

1. 概要分析へ戻る導線と「詳細分析」の見出し
2. 3・6・12か月preset、開始月・終了月、集計対象、表示ボタン
3. 期間の支出・収入・収支、月平均支出、最大支出月
4. 月別推移。見出し横の「支出」「収入」切替で系列を選ぶ、横軸＝月・縦軸＝金額の縦棒グラフ（`AC-ANA-015-1`）
5. 貯金額の推移（累積収支）の棒グラフと注記
6. 期間全体の支出カテゴリ構成。概要分析と同じ円グラフ（既定）と棒グラフの切替
7. グループ対象の場合だけメンバー別の支出額（負担額）・受取額。支払額の列は表示しない (AC-TXN-018-4)
8. 月別の支出・収入・符号付き収支・累積収支を持つ数値表

- presetは44 x 44 CSS pixel以上のリンクとして即時適用し、任意期間・対象はGET formの「表示する」でまとめて適用する。form入力中は現在の結果を残す。
- 開始月・終了月は`type="month"`の入力欄とし、320px・375px・iOS Safariで各列幅に収まり、高さ44px以上、値の左揃え、選択欄と同じ枠線・角丸で表示する。隣の入力欄やカードの外へはみ出さず、値が空でも高さを縮めない（`AC-ANA-009-7`）。
- 貯金額の推移は横軸を月、縦軸を累積収支とする1系列の棒グラフで、各月の棒は0円の基準線から正なら上、負なら下へ伸びる。太さは24px以下で等間隔に並べ、赤字の棒は支出と同じ赤系の色で示す。0円の基準線と最大値・最小値・開始月・終了月の文字ラベルを持ち、色だけに意味を置かない。グラフは`aria-hidden`の装飾とし、同じ値を数値表の「累積収支」列で示す。「期間開始時を0円として計算」と注記する（`AC-ANA-013-1`〜`AC-ANA-013-3`）。
- 月別推移は横軸を月、縦軸を金額とする1系列の縦棒グラフで、初期表示は支出、見出し横の44 x 44 CSS pixel以上の「支出」「収入」ボタン（`aria-pressed`）で即時に切り替える。切替はURL・再取得を伴わない。棒は0円の基準線から上へ伸び、太さ24px以下で等間隔に並べ、最大値・0円のラベルと月のラベル（6か月以下は各月、7〜12か月は終了月を含む1か月おき、13か月以上は開始月・終了月）を文字で添える。支出は赤系、収入は緑系で塗るが、系列はボタンの選択状態でも示す。グラフは`aria-hidden`の装飾とし、同じ値を数値表の支出・収入列で示す（`AC-ANA-015-1`〜`AC-ANA-015-3`）。
- 月別推移の棒、カテゴリ構成の円グラフ・棒は装飾とし、名称、年月、金額、割合をテキストで併記する。hover、色、扇形の角度、棒の長さだけに情報を置かない。カテゴリ構成の表示形式切替は概要分析と同じ挙動とする（`AC-ANA-014-1`〜`AC-ANA-014-3`）。
- 320pxと375 x 812では横スクロールを発生させず、月別数値表は見出し付きの月別カード行へ変形する。
- 520px以下では月別・メンバー別の各金額セルに項目名を表示する。広い画面ではセル内ラベルを隠して列見出しを使い、表の見出しとの関連と重複しない読み上げを全幅で維持する（`AC-ANA-009-6`）。月別表は4値（支出・収入・収支・累積収支）を2列2行のカード行へ、メンバー別表は3値を1行3列へ変形する。
- 1280 x 800ではフィルタと期間指標、推移とカテゴリを2カラムへ適応させ、メンバー比較と数値表は読みやすい幅を使う。
- 取引がない期間も期間内の月を0円で表示する。不正条件は取引を読まずに既定6か月へ戻る導線を、取得失敗は古い値を出さず再試行を表示する。

## 13. 予算

標準URLは`/groups/{groupId}/budgets?month=YYYY-MM`とし、設定ハブの「予算」行と分析概要の予算カードから遷移する。共通ナビゲーションの現在地は「設定」とする。閲覧はアクティブメンバー、設定・改定・停止はowner/adminに限る。詳細は[`13-budget-management.md`](13-budget-management.md)を正本とする。

375 x 812では次の順に縦配置し、グループ予算・実績・残額・状態を最初のスクロール前に確認できることを目標とする。

1. 選択月と前月・翌月操作（44 x 44 CSS pixel以上）
2. グループ予算カード（予算額、実績、残額、消化率、装飾の進捗バー、順調・注意・超過の状態ラベル、適用開始月）
3. カテゴリ別予算の縦一覧（カテゴリ名、予算、実績、残額、消化率、状態ラベル）と未配分額
4. 改定履歴（開始月と予算額。停止改定は「停止」）
5. owner/adminかつ当月以降の月だけ、予算フォームと停止操作

- 横スクロールする表を使わず、320px幅でも金額・状態・操作が重ならない。金額は省略せず表示し、超過時の残額は「超過 ￥x」と明示して色だけに依存しない。
- 予算未設定の月は説明文を表示し、owner/adminには設定フォームを続けて表示する。memberには操作を出さず「予算の設定はオーナーと管理者が行います。」と示す。過去月では「過去月の予算は変更できません。」と示す。
- フォームの金額欄（グループ予算・各カテゴリ予算）は`inputmode="none"`としてOSの仮想キーボードを開かず、取引入力・固定費と同じ画面内テンキー（1〜9、0、00、1文字削除）で入力する。テンキーは選んだ金額欄の直下へフォーム内に静的に開き、選択中の欄だけへ反映し、金額欄以外へfocusが移ると閉じる。閉じている間は金額欄をタップすると開くことを金額欄の近くへ短く示す。
- 入力中にカテゴリ予算の合計と未配分額を即時表示し、合計がグループ予算を超えるときは送信を無効化する。
- 送信ボタンは、選択月に既存改定があるときは「予算を保存」、適用改定が別の月のときは「この月から変更」、予算未設定のときは「予算を設定」とする。停止は「この月から停止する」の後に確認文と確定操作を表示する。
- 入力不備は該当欄の近く、権限不足・競合・通信失敗はフォーム全体のエラーとして表示する。
- 1280 x 800ではグループ予算・改定履歴と、カテゴリ内訳・フォームを2カラムへ適応させてよい。

## 14. スタイル構成

- `src/app/styles.css`（global）に置くもの: デザイントークン（CSS変数）、reset、基本タイポグラフィ、`src/app`のpage・layout・loading・errorが使うroute shell（例: `protected-shell`、`app-header`、`group-route-layout`、各routeのpage marker）、複数機能が共有するプリミティブ（button・link・form message・status・empty state・見出し装飾）。
- 機能のpresentationコンポーネントだけが使うスタイルは、当該presentationディレクトリに併置した機能単位のCSS Modules（例: `src/modules/calendar/presentation/calendar.module.css`）で管理し、コンポーネントからimportして参照する。
- module CSS内からglobalクラスと組み合わせる複合セレクタは`:global(...)`で明示する。globalへ機能固有セレクタを追加しない。
- どの機能からも使われないセレクタを残さない。

## 15. アクセシビリティ・表記

- formには視認できるlabelと、関連付けられたエラーメッセージを表示する。
- dialogとsheetはfocusを閉じ込め、閉じた後に元の操作へfocusを戻す。

- 削除操作はiconだけでなく文字labelも表示する。
