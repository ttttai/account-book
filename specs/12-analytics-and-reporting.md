# 統計ダッシュボード・詳細分析仕様

状態: 概要分析・詳細分析（第1・第2段階）承認済み

バージョン: 0.2.3

対象リリース: MVP後・分析フェーズ

## 1. 目的

利用者がスマートフォンで数秒以内に当月の家計状態を把握し、必要な場合だけ別画面で期間・対象・カテゴリを変えて詳細を分析できるようにする。

概要画面は判断に必要な少数の指標へ絞り、詳細分析、予算、LINEレポートの計算定義を共通化する。グラフだけで金額の意味を伝えず、正確な数値とテキストを常に併記する。

## 3. 用語と金額の意味

| 用語     | 定義                                                                                       |
| -------- | ------------------------------------------------------------------------------------------ |
| 支出     | グループ対象では支出取引を1件につき1度だけ数えた金額。メンバー対象ではそのメンバーの負担額 |
| 支払額   | 選択メンバーが支払者である支出取引の金額。負担額と混在させない                             |
| 収入     | グループ対象では収入取引の合計。メンバー対象ではそのメンバーが受取者である収入の合計       |
| 収支     | 同じ期間・対象の`収入 − 支出`。JPY整数で計算する                                           |
| 前月比   | 選択月と前月との差額。前月に対する比率（パーセント）は算出・表示しない                     |
| 期間支出 | 選択期間・対象の支出合計。カテゴリ別支出の合計と常に一致する                               |

割合は表示値であり、金額計算には使用しない。割合を表示する場合は整数パーセントへ四捨五入する。前月比は差額だけを表示し、前月に対する比率は算出・表示しない（比較元が0円でも`比較なし`などの代替表示を行わない）。

概要分析の集計対象は、ホームカレンダーと同じ`group`・`self`・`member`とし、同じ月・同じ対象ではカレンダーの月間合計と一致させる。メンバー対象の支出は負担額であり、立て替えた支払額を支出として数えない（`CAL-010`と同じ定義）。

固定費（`REC-*`）は、カレンダーと同じ規則で選択月へ展開した擬似取引として集計へ含める。展開結果はDBへ保存せず、単発取引とは別経路で作るため二重集計は発生しない。取引の読み取りと展開は`transactions`モジュールの`listMonthlyTransactions`（`05-api-and-application-boundaries.md`の共有読み取り境界）を経由し、カレンダーと同じ入力から集計する。

## 4. 機能要件

### 4.1 第1段階（実装対象）

- `ANA-001` アクティブメンバーは選択グループの概要分析を閲覧できる。
- `ANA-002` 概要分析は選択月の支出、収入、収支を正確なJPY整数で表示する。
- `ANA-003` 概要分析は前月との差額を符号付きで表示する。前月に対する比率は表示しない。
- `ANA-004` 概要分析は支出カテゴリ上位5件と残りの合計を表示する。
- `ANA-005` 概要分析は選択月を前月・翌月へ変更でき、月と集計対象をURLへ保持する。
- `ANA-009` グラフと同じ内容を数値で確認でき、グラフを見なくても値と意味を理解できる。
- `ANA-010` 収入を支出、メンバー負担額、メンバー支払額へ混入させない。
- `ANA-011` 予算機能が有効な月だけ、概要分析に予算消化額・残額・消化率を表示する。
- `ANA-012` 詳細分析とLINE等の定期レポートは、画面と同じ認可済み集計サービスを利用し、別実装で金額を再計算しない。

### 4.2 第2段階（実装対象、Issue #56）

- `ANA-006` 詳細分析は3か月、6か月、12か月、および最大24か月の任意月範囲を選択できる。
- `ANA-007` 詳細分析はグループ全体、自分、指定メンバーを分析対象にできる。
- `ANA-008` 詳細分析は月別の支出・収入・収支推移、カテゴリ別支出、メンバー別の負担額・支払額・受取額を表示する。
- `ANA-013` 詳細分析は期間の開始月から各月までの収支（収入−支出）の累積和を、貯金額の推移として棒グラフと数値で表示する。

詳細分析は上記に加え、選択期間の支出・収入・収支合計、1か月あたり平均支出、最大支出月を表示する。平均支出は期間支出を月数で割ってJPY整数へ四捨五入し、取引がない月も期間内の1か月として数える。最大支出月は同額の場合に新しい月を採用し、全月0円の場合は「該当なし」とする。これらは判断に有用で、追加の個人情報や外部データを必要としない派生値に限定する。

累積収支は、期間の開始月の直前を0円とし、各月の収支（収入−支出）を開始月から当該月まで順に加算した符号付きJPY整数とする。取引がない月は0円の収支として前月の累積値を引き継ぐ。最終月の累積収支は期間の収支合計と一致する。期間開始前の残高、口座残高、他グループの値は含めず、画面には「期間開始時を0円として計算」と注記する。集計対象がself・memberのときは、その対象の負担額と受取額から求めた収支を累積する。

## 5. 画面仕様

### 5.1 概要分析

標準URLは`/groups/{groupId}/analytics?month=YYYY-MM&scope=group|self|member&member={membershipId}`とする。`month`と`scope`の未指定はグループのタイムゾーン上の当月・グループ全体として扱う。

分析機能のリリース時、グループ内の主要ナビゲーションを「ホーム、履歴、入力、分析、設定」の5項目へ拡張する。320px幅でも各項目のタップ領域を44 x 44 CSS pixel以上確保し、ラベルを省略しない。デスクトップは同じ順序のサイドナビゲーションへ適応する。

375 x 812の初期viewportでは、次を縦方向に表示する。

1. 選択月と前月・翌月操作
2. 集計対象（グループ・自分・メンバー）。自分以外のアクティブメンバー数に応じて枠を切り替える
3. 支出・収入・収支の3指標
4. 前月との差額（符号付き。比率は表示しない）
5. グループ対象で予算がある場合は予算進捗（予算額、実績、残額、消化率、状態ラベル、予算画面への導線）
6. 支出カテゴリ上位の横棒グラフと数値
7. ホームカレンダー・履歴への導線

集計対象の枠は、認可済みcontextから得た自分以外のアクティブメンバー数に応じて次のとおり表示し、複数行へ折り返さない。

- 0人: 「グループ」「自分」の2枠を表示する。
- 1人: 「グループ」「自分」「{メンバー名}」の3枠を表示し、3枠目をそのメンバーへの直接リンクにする。
- 2人以上: 「グループ」「自分」「メンバー」の3枠を表示し、3枠目をホームカレンダーと同じメンバー選択欄にする。候補は自分以外のアクティブメンバーだけとし、選択後は閉じた状態で選択中の表示名を枠へ示す。

いずれの場合も各枠のタップ領域は44 x 44 CSS pixel以上を保ち、リンクは`month`・`scope`・`member`をURLへ保持する。メンバー数の判定と候補には、クライアントから渡された値ではなくサーバーqueryが返す認可済みのメンバーDTOだけを使う。

支出・収入・収支は最初のスクロール前に確認できることを目標とする。横スクロールするカード列は使用しない。金額は`￥123,456`のように省略せず表示し、グラフ上の短縮表記を使う場合も直近に正確な数値を併記する。

空状態では0円の指標と「この月の取引はまだありません。」を表示し、分析不能をエラーとして扱わない。取得失敗時は前回値を最新値として誤表示せず、再試行操作を提供する。月・集計対象・メンバーの指定が不正な場合は、取引を読み込まずに検証エラーを表示し、当月・グループ表示へ戻る導線だけを出す。

### 5.2 詳細分析（段階2）

標準URLは`/groups/{groupId}/analytics/details?start=YYYY-MM&end=YYYY-MM&scope=group|self|member&member={membershipId}`とする。未指定時はグループのタイムゾーン上の当月を終了月とする直近6か月・グループ全体を表示する。3・6・12か月のpresetと、開始月・終了月による1〜24か月の任意範囲を提供し、期間・scope・membershipをsearch paramsへ保持する。不正期間、24か月超、逆順、scopeと一致しないmembership、別グループまたは削除済みmembershipは取引を読まずに検証エラーとする。

モバイルでは期間、対象、期間合計・月平均・最大支出月、月別推移、貯金額の推移（累積収支）、カテゴリ構成、メンバー比較、数値表の順に縦配置する。概要分析からは選択月を終了月とする6か月表示へ1タップで移動でき、詳細分析から概要へ戻れる。フィルタはGET formで明示的に「表示する」を押して適用し、入力中に現在の結果を消さない。遷移開始後は詳細分析routeのloading表示を使い、共通ナビゲーションは親layoutに残す。

月別推移は支出・収入・収支の正確な数値表を主情報とし、支出と収入の相対量を横棒で補助表示する。棒は`aria-hidden`の装飾とし、収支は符号を付け、色だけで黒字・赤字を伝えない。

貯金額の推移は、横軸を期間内の月、縦軸を累積収支とする1系列の棒グラフで表示する。各月の棒は0円の基準線から、累積収支が正なら上へ、負なら下へ伸ばす。縦軸は必ず0円を含む範囲とし、0円の基準線を引き、最大値・最小値の符号付き金額と開始月・終了月のラベルを文字で添える。棒の太さは24px以下で月数に応じて等間隔に並べる。赤字（累積収支が負）の棒は月別推移の支出と同じ赤系の色、黒字と0円の棒はaccent色で示すが、棒の向きと数値表の符号でも同じ意味を伝え、色だけに依存しない。グラフは`aria-hidden`の装飾とし、同じ値を月別数値表の「累積収支」列で符号付きJPY整数として表示する。JavaScriptやhoverに依存せずServer Componentで描画し、1か月だけの期間でも棒1本として表示する。累積収支が0円の月は基準線上の最小高さの棒として月の存在を示す。

開始月・終了月の入力欄は`type="month"`を使い、320px・375px・iOS Safariのいずれでも、それぞれの列幅に収まり、高さ44px以上、値の左揃え、集計対象・メンバーの選択欄と同じ枠線・角丸で表示する。値が空でも高さを縮めず、隣の入力欄やカードの外へはみ出さない。カテゴリ構成は期間全体の支出をカテゴリIDで集計して全件を降順表示する。メンバー比較はグループ対象のときだけ表示し、各アクティブメンバーの負担額・支払額・受取額を別列・別ラベルで表示する。selfまたはmember対象では選択対象の値と重複するため表示しない。

空状態では期間指標を0円、数値表へ期間内の各月を0円で表示し、「この期間の取引はまだありません。」と示す。取得失敗は古い結果を表示せず再試行を提供する。320px・375 x 812では横スクロールを発生させず、広い数値表はカード状の月別行へ変形する。1280 x 800ではフィルタと主要指標、推移と構成を複数カラムへ適応できる。

カード状表示でも、各金額の直前に「支出・収入・収支」または「負担額・支払額・受取額」の項目名を見える文字で表示する。520px以下では各セルにラベルを表示し、広い画面では列見出しを使ってセル内ラベルを隠す。表の列見出し・行見出しの関連は全幅で保持し、視覚的な補助ラベルをスクリーンリーダーへ重複して読み上げさせない（review: 2026-09-03-analytics-details-mobile-labels）。

## 6. グラフ規則

- カテゴリ構成はモバイルで比較しやすい横棒を標準とする。円グラフだけを唯一の表示にしない。
- 横棒は`role`を持つ意味のある要素として実装し、カテゴリ名、正確な金額、構成比テキストを併記する。棒の長さと色だけで値を伝えない。
- 支出カテゴリは取引のカテゴリIDで集計し、現在の表示名・色を表示に使う。アーカイブ済みカテゴリも過去データに含める。
- 上位5カテゴリ以外は「その他のカテゴリ」として合算し、既存の「その他」カテゴリとは別ラベルにする。
- 累積収支のように正負をとる時系列は、0円の基準線から上下へ伸びる棒で示す。縦軸は1本だけにし、2軸グラフは使わない。1系列のグラフには凡例を置かず、見出しで系列名を示す。
- すべての集計領域に見出し、対象月、集計対象、単位を付ける。
- hoverだけに情報を置かず、touch、keyboard、screen readerで同じ値へ到達できるようにする。

## 7. データ・サーバー境界

分析専用の永続集計テーブルとmigrationを追加しない。認可済みグループと指定期間の取引・負担行・固定費設定をサーバーで集計し、表示に必要な最小DTOだけをClient Componentへ渡す。既存の`transactions (group_id, category_id, transaction_date)`索引と月範囲条件を使う。

サーバー境界は次の2つを公開する。

| 関数                                          | 用途                                           | 対象範囲  |
| --------------------------------------------- | ---------------------------------------------- | --------- |
| `getAnalyticsOverview(groupId, searchParams)` | 概要分析画面。選択月と前月比較のDTOを返す      | 2か月     |
| `getAnalyticsPeriodSummary(request)`          | 詳細分析・LINEレポートが再利用する期間サマリー | 1〜24か月 |
| `getAnalyticsDetails(groupId, searchParams)`  | 詳細分析画面の期間・カテゴリ・メンバーDTO      | 1〜24か月 |

3関数は同じ内部集計処理を共有し、同じ入力に対して同じ金額を返す（`ANA-012`）。認証・所属確認は`groups`モジュールの`resolveGroupReadContext`、取引の読み取りと固定費の展開は`transactions`モジュールの`listMonthlyTransactions`を使い、分析module内では集計純関数だけを持つ。詳細分析の1要求では月次取引を1回だけ読み、その結果から選択対象・カテゴリ・全アクティブメンバーを集計する。呼び出しごとに認証済みGoogle sessionとアクティブ所属を確認し、`route params`・`search params`をschema検証する。`scope=member`は同一グループのアクティブmembershipだけを許可する。24か月を超える範囲、不正な月、開始月が終了月より後の要求はfail closedで拒否し、取引を読み込まない。

共有cacheは使用しない。性能測定で必要性が確認された場合だけ、グループ・期間・対象を含むkey、取引・予算更新時の無効化、グループ分離テストを先に仕様化する。

LINEレポートは生の取引行を受け取らず、`getAnalyticsPeriodSummary`が返す期間サマリーDTOを利用する。LINE連携のtoken、送信先、同意、解除、再送、失敗監視は本仕様の実装範囲外とし、通知仕様で別途承認する。

予算（`BUD-*`、[`13-budget-management.md`](13-budget-management.md)）は、概要DTOの任意項目`budget`として渡す。概要分析は集計対象がグループのときだけ、認可済みcontextと選択月から予算moduleの`loadAppliedBudgetRevision`で適用改定を読み、既に集計した選択月の`AnalyticsMonthTotals`を予算moduleの純関数`calculateBudgetProgress`へ渡して予算額・実績・残額・消化率・状態ラベルを作る。取引を二重に読まず、金額を別実装で再計算しない。予算がない月と自分・メンバー対象では予算領域を表示しない。予算カードから同じ月の予算画面へ遷移できる。
