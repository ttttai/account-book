## 変更・実装フロー

すべての要件は次の順序で進める。

```text
下書き → レビュー済み → 承認済み → テスト作成 → 実装済み → 検証済み
```

手順:

1. 実装前に仕様を作成または更新する。
2. 仕様同士の整合性、安全性、実装可能性、MVP範囲を確認する。
3. `reviews/YYYY-MM-DD-<slug>.md`へレビュー結果を残す（書き方は`reviews/README.md`）。
4. 承認された受け入れ条件に対応するテストを作る。
5. テストと仕様に従って実装する。
6. 検証後、仕様の状態を更新する。

対象仕様が`reviews/`のレビューファイルで承認されるまで、本実装を開始してはならない。`R-001`〜`R-077`の過去のレビューは`09-spec-review.md`に残す。

## 変更ルール

- ユーザー向け動作の変更は、実装前または実装と同じコミットで仕様を変更する。
- 表示上の意味、認可、金額計算、削除動作を変える場合は、`reviews/`へ仕様レビューを追加する。`09-spec-review.md`へは追記しない。
- 自動生成APIドキュメントは、プロダクト動作の正本にしない。要件と受け入れ条件を正本とする。
