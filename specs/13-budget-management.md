# 予算管理仕様

状態: 承認済み（review: 2026-09-04-budget-management、2026-09-04-pr101-budget-review、2026-09-04-budget-amount-keypad）

バージョン: 0.2.3

対象リリース: MVP後・予算フェーズ（Issue #54）

## 1. 目的

グループ全体と支出カテゴリごとの月間支出上限を設定し、利用者が当月の消化状況をスマートフォンで数秒以内に確認できるようにする。予算超過は取引登録を妨げず、判断材料と警告として扱う。予算の変更は適用開始月を持つ改定履歴として保存し、過去月の表示を遡って変えない。

## 2. 用語

| 用語         | 意味                                                                                                |
| ------------ | --------------------------------------------------------------------------------------------------- |
| グループ予算 | 対象月のグループ支出の上限額。JPY整数                                                               |
| カテゴリ予算 | グループ予算の内訳として支出カテゴリごとに設ける上限額。任意                                        |
| 改定         | 適用開始月から後続月へ継続する予算設定の1件。`budget_revisions`の1行                                |
| 適用改定     | 対象月以前で最も新しい開始月を持つ改定。対象月の予算はこの改定で決まる                              |
| 停止改定     | 予算額を持たない`disabled`状態の改定。開始月以降は予算未設定として扱う                              |
| 実績         | 対象月のグループ支出。1取引につき1度だけ数え、収入と負担額を含めない（`ANA-*`の「支出」と同じ定義） |
| 残額         | `予算額 − 実績`。超過時は負数                                                                       |
| 消化率       | `実績 ÷ 予算額`の表示用整数パーセント。DBへ保存しない                                               |
| 未配分額     | `グループ予算 − カテゴリ予算の合計`。カテゴリ予算を持たない支出の余裕                               |

## 3. 機能要件

- `BUD-001` ownerまたはadminは、適用開始月を指定してグループ月間予算を設定できる。
- `BUD-002` ownerまたはadminは、グループ予算の内訳として支出カテゴリ別予算を設定できる。
- `BUD-003` アクティブメンバーは予算額、実績、残額、消化率を閲覧できる。
- `BUD-004` 予算実績はグループ支出を1取引につき1度だけ数え、収入と負担額を含めない。
- `BUD-005` 予算は適用開始月から後続月へ継続し、後の改定が過去月の予算を変更しない。
- `BUD-006` ownerまたはadminは現在月または将来月から予算を改定・停止できる。
- `BUD-007` 予算到達率が80%未満、80%以上100%未満、100%以上の状態を、色だけに依存せず表示する。
- `BUD-008` 予算超過中でも、有効な取引の登録・編集を拒否しない。
- `BUD-009` 予算更新は楽観的lockを使い、同時編集を暗黙に上書きしない。
- `BUD-010` 分析概要と予算画面は同じ実績集計定義を利用し、同じ月の予算・実績・残額が一致する。

## 4. 権限

| 操作                   | owner | admin | member | 非メンバー |
| ---------------------- | ----: | ----: | -----: | ---------: |
| 予算・実績の閲覧       |    可 |    可 |     可 |       不可 |
| 予算の設定・改定・停止 |    可 |    可 |   不可 |       不可 |

閲覧はアクティブメンバー全員に許可する。更新はDBの`security definer`関数内でowner/adminを再確認し、テーブルへ直接の更新権限を付与しない。

## 5. 予算の意味と規則

- 通貨はグループ通貨とし、初回実装はJPYだけを扱う。
- 予算額は`1`以上`9,007,199,254,740,991`以下の整数とする。金額計算に浮動小数点を使わない。
- 有効な改定ではグループ予算を必須、カテゴリ予算を任意とする。
- カテゴリ予算の合計はグループ予算以下とする。差額は未配分額として表示する。
- 同じカテゴリを1つの改定内へ重複設定できない。
- 収入カテゴリ、別グループのカテゴリ、アーカイブ済みカテゴリを新しい改定へ設定できない。
- 過去に設定したカテゴリがその後アーカイブされても、既存改定の内訳と実績表示では現在の名称・色を維持する。
- カテゴリ実績は取引のカテゴリIDで集計する。カテゴリ予算を持たないカテゴリの支出は、グループ予算の実績にだけ含める。
- 残額は`予算額 − 実績`とし、超過時は負数として扱い、画面では「超過 ￥x」と明示する。
- 消化率は`実績 ÷ 予算額`を整数パーセントへ四捨五入した表示値とする。除算・乗算の浮動小数点誤差で0.5%の境界が切り下がらないよう整数演算で丸める（予算1,000円・実績145円は15%）。100%を超えても切り詰めない。
- 状態は整数比較で判定し、表示用の四捨五入値を判定に使わない。

| 状態   | 条件                               | ラベル |
| ------ | ---------------------------------- | ------ |
| `ok`   | `実績 × 5 < 予算額 × 4`（80%未満） | 順調   |
| `warn` | `実績 < 予算額`かつ80%以上         | 注意   |
| `over` | `実績 >= 予算額`（100%以上）       | 超過   |

- 予算の設定・改定・停止は取引を更新しない。取引の登録・編集・削除は予算の状態を理由に失敗しない（`BUD-008`）。

## 6. 期間と改定

予算は月ごとに複製せず、適用開始月を持つ改定履歴として保存する。対象月には、同月以前で最も新しい開始月の改定を適用する。適用改定がない月、または適用改定が停止改定の月は予算未設定として扱う。

```text
2026-09から300,000円
2026-12から320,000円
2027-03から停止

2026-08以前 : 予算なし
2026-09〜11 : 300,000円
2026-12〜2027-02 : 320,000円
2027-03以降 : 予算なし（履歴は残る）
```

- 開始月はグループのタイムゾーン上の当月以降に限る。過去月を開始月とする改定の作成、および開始月が過去月の既存改定の変更・停止を許可しない。判定はDB関数がグループの`timezone`から当月を求めて行い、クライアントの日時を信用しない。
- 当月の改定は許可する。当月の実績は変更後の予算に対して即時に再評価する。
- 同じグループ・同じ開始月の改定は1件だけとする。既存の改定がある月は`expectedVersion`を添えた更新、ない月は新規作成として扱い、期待と実際が食い違う要求（作成のつもりで既に存在する、更新のつもりで存在しない、versionが古い）は競合として拒否する。
- 停止は予算額を0円にせず、対象月を開始月とする停止改定を作成または更新する。停止改定はカテゴリ内訳を持たない。
- 停止済みの月へ再度予算を設定すると、同じ開始月の改定を有効状態へ更新する。
- 改定の削除は提供しない。

## 7. 画面仕様

標準URLは`/groups/{groupId}/budgets?month=YYYY-MM`とする。`month`未指定はグループのタイムゾーン上の当月とする。設定ハブの「予算」行と、分析概要の予算カードから遷移できる。共通ナビゲーションの現在地は「設定」とする。閲覧はアクティブメンバー、設定・改定・停止はowner/adminに限る。

375 x 812では次の順に縦配置し、グループ予算・実績・残額・状態を最初のスクロール前に確認できることを目標とする。

1. 選択月と前月・翌月操作（44 x 44 CSS pixel以上）
2. グループ予算カード: 予算額、実績、残額、消化率、装飾の進捗バー、状態ラベル（順調・注意・超過）、適用開始月
3. カテゴリ別予算の縦一覧: カテゴリ名、予算、実績、残額、消化率、状態ラベル。末尾に未配分額
4. 改定履歴: 開始月と予算額（停止改定は「停止」）を新しい順に一覧
5. owner/adminかつ選択月が当月以降のときだけ、予算フォームと停止操作
6. 予算未設定の月は、予算で何が分かるかの説明を表示し、owner/adminには設定フォームを続けて表示する

- 横スクロールする表を使用しない。320px幅でも金額・状態・主要操作が重ならない。
- 金額は`￥123,456`のように省略せず表示する。残額は正のときそのまま、超過時は「超過 ￥x」と表記し、色だけで意味を伝えない。
- 進捗バーは`aria-hidden`の装飾とし、数値とラベルで同じ内容を伝える。棒の長さは100%で切り詰めてよい。
- memberには設定・改定・停止の操作を表示せず、「予算の設定はオーナーと管理者が行います。」と示す。
- owner/adminが過去月を表示しているときは操作を表示せず、「過去月の予算は変更できません。」と示す。
- 予算フォームの入力順は、グループ予算、カテゴリ別予算（アクティブな支出カテゴリを並び順で列挙、空欄は未設定）とする。
- 金額欄は`inputmode="none"`としてOSの仮想キーボードを開かず、取引入力・固定費と同じ画面内テンキー（1〜9、0、00、1文字削除）で円単位の整数を入力する（`TXN-014`・`REC-010`と同じ規則）。テンキーは`transactions`モジュールの公開エントリーポイント経由で共有し、予算側へ複製しない。
- テンキーは金額欄（グループ予算・各カテゴリ予算）を選んだときにその欄の直下へフォーム内に静的に開き、キー操作は選択中の金額欄だけへ反映する。別の金額欄を選ぶとその欄の直下へ移り、金額欄以外の入力欄や操作へfocusが移ると閉じる。テンキー自体の操作では開閉と入力済みの金額を変えない。閉じている間は金額欄をタップすると開くことを金額欄の近くへ短く示す。
- 物理キーボードとスクリーンリーダーからの入力・読み上げは開閉状態にかかわらず維持し、各キーはフォームを送信しない。先頭0と安全な整数の上限は取引入力と同じ規則で扱う。開いたキーが下部ナビゲーションへ隠れる場合は隠れない位置まで表示位置を移動し、各キーは375 x 812と320pxで44 x 44 CSS pixel以上とする。
- 金額欄は入力中も取引入力（`AC-TXN-014-10`）・固定費と同じ3桁区切りで表示する（`300,000`）。表示用の`input`は`name`を持たず、送信する`totalAmountMinor`・`categoryLimit:<categoryId>`は区切りなしの整数をhidden inputで送る。合計・未配分額は区切りなしの状態から計算し、物理キーボードや貼り付けで入った`,`は無視する。整形関数は`transactions`モジュールの公開エントリーポイント経由で再利用し、予算側へ複製しない（`AC-BUD-010-5`）。
- フォームは入力中に「カテゴリ予算の合計」と「未配分額」を即時に表示し、合計がグループ予算を超えるときは超過額を示して送信ボタンを無効化する。サーバー側でも同じ条件で拒否する。
- 選択月と適用改定の開始月が同じ場合は既存改定の更新（送信ボタン「予算を保存」）、異なる場合は選択月を開始月とする新規改定（「この月から変更」）、予算未設定の月は新規設定（「予算を設定」）とする。適用改定がある月の初期値には適用改定の金額を入れる。
- 月またはグループが変わったときは、金額・カテゴリ入力・保存結果・停止確認を遷移先の状態へ初期化し、別の月の未保存入力を持ち越さない。同じ月でも適用改定の開始月・状態・versionが更新されたときは、入力値を新しい改定にそろえ、古い入力値と新しい`expectedVersion`を組み合わせない。実績だけの更新では未保存入力とfocusを維持し、保存後の改定更新でも入力要素を再作成せずfocusと成功通知を維持する。
- 停止操作は「この月から停止する」を押した後に確認文と確定操作を表示し、確定で停止改定を保存する。
- 入力不備は該当欄の近く、権限不足・競合・通信失敗はフォーム全体のエラーとして表示する。競合時は他の更新があったことを説明し再読み込みを案内する。保存中は主要ボタンを無効化し、成功時は同じ月の表示を更新する。
- 1280 x 800ではグループ予算・改定履歴と、カテゴリ内訳・フォームを2カラムへ配置してよい。

### 分析概要との連携

分析概要（`12-analytics-and-reporting.md`）は、集計対象がグループのときだけ、選択月に有効な予算がある場合に予算カードへ予算額、実績、残額、消化率、状態ラベルを表示し、同じ月の予算画面へのリンクを置く。自分・メンバー対象では予算カードを表示しない（グループ予算に対する個人の消化率は定義しない）。予算が無い月は従来どおり予算領域を表示しない（`AC-ANA-011-1`）。

### 設定ハブ

設定ハブの「グループ管理」に「予算」行を追加し、全アクティブメンバーへ表示する。

## 8. データモデル

### `budget_revisions`

| column               | 型              | 説明                                          |
| -------------------- | --------------- | --------------------------------------------- |
| `id`                 | uuid PK         |                                               |
| `group_id`           | uuid FK         | 必須のグループ境界                            |
| `effective_month`    | date            | 適用開始月。月初日で保持する                  |
| `status`             | text            | `active`または`disabled`                      |
| `total_amount_minor` | bigint nullable | `active`では正のJPY整数、`disabled`では`null` |
| `version`            | integer         | 1から開始し更新ごとに加算                     |
| `created_by`         | uuid FK         | 認証ユーザー                                  |
| `updated_by`         | uuid FK         | 認証ユーザー                                  |
| `created_at`         | timestamptz     | UTC                                           |
| `updated_at`         | timestamptz     | UTC                                           |

制約:

- `(group_id, effective_month)`をuniqueにする。
- `(id, group_id)`をuniqueにし、内訳から複合外部キーで参照できるようにする。
- `effective_month`は月初日（`date_trunc('month')`と一致）に限る。
- `status = 'active'`のとき`total_amount_minor`は`1`以上`9,007,199,254,740,991`以下、`status = 'disabled'`のとき`null`。
- `version >= 1`。

### `budget_category_limits`

| column               | 型               | 説明                       |
| -------------------- | ---------------- | -------------------------- |
| `budget_revision_id` | uuid PK/FKの一部 |                            |
| `category_id`        | uuid PK/FKの一部 | 同じグループの支出カテゴリ |
| `group_id`           | uuid FK          | 必須のグループ境界         |
| `amount_minor`       | bigint           | 正のJPY整数                |
| `created_at`         | timestamptz      | UTC                        |

制約:

- `(budget_revision_id, category_id)`を主keyにする。
- `budget_revision_id`と`category_id`は`group_id`を含む複合外部キーで同じグループへ固定する。
- 停止改定には内訳を作らない。合計が親改定のグループ予算を超えない状態だけをDB commandでcommitする。

### インデックス

```text
budget_revisions(group_id, effective_month DESC)
budget_category_limits(category_id, budget_revision_id)
```

### RLS

両テーブルでRLSを有効化・強制し、selectは`app_private.is_active_group_member(group_id)`を満たすアクティブメンバーだけに許可する。insert/update/deleteはテーブルへ直接付与せず、`security definer`関数だけが行う。

## 9. サーバー境界

```text
Query:   getGroupBudget(groupId, searchParams)
         loadAppliedBudgetRevision(context, month)      // 分析概要が予算進捗を作るための共有読み取り
Command: setGroupBudget(groupId, effectiveMonth, expectedVersion | null, totalAmountMinor, categoryLimits)
         disableGroupBudget(groupId, effectiveMonth, expectedVersion | null)
```

- `getGroupBudget`は`groupId`と`month`を検証し、共有境界`resolveGroupReadContext`で認証・アクティブ所属を確認してから、選択月の適用改定、改定履歴、アクティブな支出カテゴリ、同月の実績を返す。実績は`transactions`モジュールの`listMonthlyTransactions`で読み、分析と同じ純関数`aggregateAnalyticsMonth`（グループ対象）で集計する。予算moduleは`transactions`テーブルを直接読まない。
- 不正な`month`は取引と予算を読み込まずに検証エラー状態を返し、当月へ戻る導線だけを出す。未認証・非メンバー・不正な`groupId`は存在を明かさず`null`を返す。
- 予算進捗（実績、残額、消化率、状態、カテゴリ別、未配分額）は純関数`calculateBudgetProgress(revision, monthTotals)`で作る。予算画面と分析概要は同じ関数を使い、クライアントで再計算しない。
- 分析概要は、認可済みcontextと選択月から`loadAppliedBudgetRevision`で適用改定を読み、既に集計した選択月の`AnalyticsMonthTotals`を渡して予算進捗DTOを作る。取引を二重に読まない。
- `setGroupBudget`と`disableGroupBudget`はServer Actionで入力をschema検証したうえで、`security definer`のDB関数`set_group_budget`・`disable_group_budget`を1回呼び、改定本体と内訳を同一transactionで保存する。DB関数はowner/admin、グループのタイムゾーン上の当月以降であること、金額範囲、カテゴリの同一グループ・支出種別・未アーカイブ・重複なし、合計がグループ予算以下であること、`expectedVersion`を再検証する。
- Clientが渡した実績、残額、消化率、カテゴリ合計、未配分額を信用しない。
- DB関数の失敗は`40001`（競合）、`P0002`（対象なし）、`42501`・`28000`（権限不足・未認証）、`22023`（入力不正）、`23505`（同月の同時作成、競合として扱う）を分類して利用者向けメッセージへ変換し、サーバーlogへ操作名とcodeだけを記録する（`NFR-OPS-008`）。
- Server Componentはサーバー専用queryを直接呼び、Client Componentへは最小DTOだけを渡す。DB行、ユーザーID、tokenを渡さない。
- 個人の家計データに対する共有cacheを追加しない。

## 11. 初回実装から延期する範囲

- メンバー個別予算
- 日・週・年単位の予算
- 予算の翌月繰越
- 予算案の承認フロー
- 予算に基づく取引登録の強制停止
- 自動予算提案
- 改定の削除
- LINEによる予算警告（通知仕様で別途扱う）
