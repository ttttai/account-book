# 詳細分析に金額帯別の支出を追加する

状態: 実装確認済み
レビュー日: 2026-10-22
ブランチ: feat/analytics-amount-bands
対象仕様: `specs/12-analytics-and-reporting.md`（4.2、5.2、5.5、6、7、9）、`specs/01-product-requirements.md`（`ANA-017`、`ANA-018`）、`specs/02-use-cases.md`（`AC-ANA-017-2`、`AC-ANA-017-3`、`AC-ANA-018-1`〜`AC-ANA-018-4`）、`specs/03-screen-specification.md`（詳細分析）、`specs/07-acceptance-test-plan.md`、`specs/15-e2e-testing.md`（E2E-010）
関連ID: `ANA-018`、`AC-ANA-018-1`〜`AC-ANA-018-4`を追加。変更: `ANA-017`、`AC-ANA-017-2`、`AC-ANA-017-3`。維持: `ANA-008`、`ANA-009`、`ANA-012`、`CAL-010`、`REC-005`、`TXN-018`

## 指摘

利用者から「分析で、何円から何円の支出が多いかも見たい」と要望があった。既存の分析はカテゴリ別と月別の集計だけで、少額の出費が積み重なっているのか、大きな出費が支出の多くを占めるのかが分からない。

表示形式を検討した結果は次のとおり。

- 縦棒のヒストグラムは、帯の名前（「1,000〜3,000円」など）が横軸に7つ並び、375pxでは重なる。月別推移で月ラベルを間引いたのと同じ問題が起きる。帯を縦に並べる横棒なら、1行に帯の名前・件数・金額・構成比を並べられ、カテゴリの棒グラフと同じ見た目になる。
- 「多い」には件数と金額の2つの意味がある。件数だけでは大きな出費の重さが、金額だけでは少額の出費の頻度が見えないため、両方をテキストで示し、棒と構成比の基準だけを切り替える。
- データから区切りを自動で決めると、期間や対象を変えるたびに帯が変わって比較できない。少額ほど細かく、高額ほど粗い固定の7帯にする。
- 1か月だけでは件数が少なく分布が見えにくいため、期間で見る詳細分析に置く。常時表示の領域は2画面分以内という制約（`AC-ANA-017-1`）があるため、折りたたみに置いて既定で展開する。

利用者と次の4点を確認し、すべて推奨どおりとした。

1. 固定費の展開分を含める。他の集計と合計が一致する。
2. 自分・メンバー対象では負担額で数える（`CAL-010`と同じ定義）。6,000円を2人で分けた支出は3,000円として「3,000〜5,000円」に入る。
3. 帯は500円未満、500〜1,000円、1,000〜3,000円、3,000〜5,000円、5,000〜1万円、1万〜3万円、3万円以上の7つにする。
4. 帯から履歴への遷移は提供しない。履歴に金額の絞り込みが必要になるため、後回しにする。

## 対応

- `ANA-018`と`AC-ANA-018-1`〜`AC-ANA-018-4`を追加した。12の5.5に、数える単位、帯の境界（下限を含み上限を含まない）、一覧、切替、構成比と棒の長さ、空状態を定めた。
- 帯の表示名は主情報のため、カテゴリ名のように省略記号で切り詰めない。320pxで長い件数・金額（例: 999件・￥9,999,999）と並んで収まらない場合だけ「〜」の後で折り返す。
- 件数0の帯も常に表示する。行の数と位置が変わらないため、期間や対象を変えても比較しやすい。
- 構成比と棒の基準は選択中の基準に従う。「件数」では全件数に対する割合と最多件数の帯に対する長さを、「金額」では期間支出に対する割合と最大金額の帯に対する長さを使う。構成比が何の割合かを切替の横の説明文で示す。見出しは折りたたみの開閉ボタンのため、切替は見出しの中ではなく内容の先頭行に置く。棒の長さを構成比ではなく最大帯に対する比にするのは、7帯のうち件数が少ない帯でも差が見えるようにするためである。
- 折りたたみの並びを「金額帯別の支出 → メンバー別 → 月別の正確な数値」とし、`ANA-017`、`AC-ANA-017-2`、`AC-ANA-017-3`へ反映した。1280 x 800では月別推移と金額帯別の支出を同じ行に並べる。
- 振り分けと割合・長さの計算は分析moduleの純関数で行い、詳細分析が既に読んだ取引集合から作る。DTOには7帯の件数・合計金額だけを加え、取引1件ごとの値は渡さない。
- 区切りの利用者設定、履歴への遷移、概要分析での表示は延期範囲（9.）に加えた。

## 安全性確認

既存の`getAnalyticsDetails`の認証・所属確認・条件検証を通った後の、同じ取引集合だけを集計する。新しい読み取り、Server Action、migration、cacheは追加しない。DTOへ加えるのは帯ごとの件数と合計金額だけで、取引ID、メモ、日付、支払者はClient Componentへ渡さない。支払額は表示しない（`TXN-018`）。

## 実装可能性確認

既存の`aggregateAnalyticsTransactions`と同じ対象金額の規則（グループは取引金額、メンバーは負担額、0円は除外）を使えば、帯の件数の合計は既存の支出件数と、金額の合計は期間支出と一致する。表示は既存のカテゴリ棒グラフと折りたたみの部品・CSSを流用できる。7帯は固定のため、月数による計算量の変化は取引件数に比例する1回の走査だけである。

## MVP範囲確認

詳細分析の1セクションの追加で、概要分析・LINE週次レポート・履歴は変えない。帯の区切りは固定とし、設定画面を作らない。

## 判定

整合性、安全性、実装可能性、MVP範囲を確認し承認する。実装開始の条件: 帯の振り分けと割合・棒の長さの純関数の単体test、金額帯別の支出の部品のComponent test、詳細分析の並びのarchitecture test、E2E-010の金額帯の確認を先に追加して失敗を確認する。実画面は320px・375 x 812・1280 x 800で確認する。

## 実装確認

- 純関数の単体test（境界値、負担額、期間外、構成比と棒の長さ、全帯0件）、部品のComponent test（初期の件数表示、金額への切替、0件の空状態）、詳細分析の並びのComponent test・architecture test、E2E-010の金額帯の確認を先に追加して失敗を確認し、実装後に成功させた。
- 単体・Component test 1,215件、architecture test 255件、E2E 30件（mobile・desktop）、lint、型検査、prettier、本番buildが成功した。
- fixtureの一時previewで320px・375 x 812・1280 x 800を確認した。いずれもページの横スクロールは無く、切替ボタンは高さ44pxで説明文と同じ行に並び、7行とも1行に収まった。初版は320pxで帯の表示名が省略記号で切れたため、帯の行だけ間隔と文字を詰めた。極端な値（999件・￥9,999,999）では、帯の表示名を「〜」の後で折り返して数値を欠かさないことを確認した。1280pxでは月別推移と金額帯別の支出が同じ行に並ぶ。
