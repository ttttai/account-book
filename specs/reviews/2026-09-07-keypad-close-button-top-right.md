# 取引入力のテンキーの「閉じる」を入力ドック右上へ移す

状態: 実装確認済み
レビュー日: 2026-09-07
ブランチ: fix/keypad-close-top-right
対象仕様: `specs/02-use-cases.md`、`specs/03-screen-specification.md`、`specs/07-acceptance-test-plan.md`、`specs/08-decisions-and-deferred-scope.md`
関連ID: `AC-TXN-014-9`を更新（追加なし）

## 指摘

- PR #126（`2026-09-07-keypad-close-button`）で承認・マージした配置（数字キー最下行の左端）に対し、ユーザーから「閉じるは右上（『すべて』の上）のほうが良い」との指摘があった。数字配列に操作キーを混ぜると、0の2列幅を解除して従来の配列を変えることになり、数字を打つ流れの中で押し間違える余地もある。
- OSの仮想キーボードでは「完了」や閉じる操作をキーボード上端の右に置くのが通例で、入力ドックの右上（「カテゴリ」見出し行の右端、「すべて」の真上）に置くと利用者の期待と一致する。
- 右上へ置くと見出し行に44 x 44 CSS pixelのタップ領域を確保する必要があり、ドックの高さが見出し行の範囲で増える。前回の「ドックの高さを変えない」条件との整合を仕様で明示する必要がある。
- 900px以上では入力ドックを固定せず、「すべて」も表示しない。閉じる操作の表示可否を決める必要がある。

## 対応

- `AC-TXN-014-9`を「入力ドックの右上（『カテゴリ』見出し行の右端、『すべて』の真上）へ置く」へ改め、テンキーの行と数字配列（00と2列幅の0）を変えないこと、ドックの高さの増加は見出し行の範囲にとどめること、カテゴリ展開中は隠すこと、900px以上では「すべて」と同様に表示しないことを明記した。
- 実装は`ExpenseForm`の入力ドック直下（fieldsetの外）へ`type="button"`の「閉じる」を置き、ドック（`position: fixed`）を基準に右上へ絶対配置する。fieldsetの外に置くため、カテゴリのgroup名（`getByRole("group", { name: "カテゴリ" })`）を汚さない。
- テンキーを開いている間だけ見出し行を2.25remへ広げ、44pxのボタンが「すべて」やカテゴリ行と重ならないようにする。閉じている間は従来の高さへ戻す。
- 共有部品`AmountKeypad`から前回追加した`onClose`と閉じるキーを取り除き、変更前の状態へ戻す。固定費・予算フォームは引き続き変更しない。
- 閉じた直後のfocusを金額欄へ戻す挙動、アクセシブルネーム「テンキーを閉じる」、E2Eの`exact: true`は前回どおり。

## 安全性確認

- Server Action、schema、DB、認可、楽観的ロックは変更しない。ボタンは`type="button"`でフォームを送信せず、金額の式状態と送信値に触れない。
- 絶対配置はドック内に限定し、900px以上（`display: contents`でドックが基準にならない表示）では表示しないため、意図しない位置へ飛ばない。

## 実装可能性確認

- 変更は`expense-form.tsx`のボタン1つとCSSの数ルールで済み、`AmountKeypad`は元へ戻すだけである。
- 375pxではドックの高さが約371px→約390px（見出し行ぶん）になるが、金額欄はテンキーを開いたときにドックへ隠れない位置へ移動する既存処理（`AC-TXN-014-7`）で見える。320pxでも同様。

## MVP範囲確認

- 対象は取引入力の閉じる操作の配置のみ。アニメーション、スワイプで閉じる操作、固定費・予算への展開は含めない。
