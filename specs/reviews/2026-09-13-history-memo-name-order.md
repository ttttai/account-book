# 履歴の2行目で支出した人の位置をメモの有無に依存させない

状態: 実装確認済み
レビュー日: 2026-09-13
ブランチ: fix/history-memo-name-order
対象仕様: `specs/02-use-cases.md`、`specs/03-screen-specification.md`、`specs/07-acceptance-test-plan.md`
関連ID: `AC-HIS-007-1`、`AC-HIS-007-3`を更新。`HIS-007`、`AC-HIS-006-2`、`AC-HIS-006-4`、`AC-HIS-007-2`、`AC-TXN-018-3`を参照（追加なし）。

## 指摘

- 旧レビュー`2026-09-11-history-spender-display`で2行目を「メモ、支出した人の表示名」の順にし、メモを残り幅で伸ばす規則にした結果、メモがある行では表示名が2行目の右端へ押し出され、メモが無い行では左端に来る。同じ一覧の中で表示名の位置が行ごとに左右へ動き、誰の支出かを上から追いにくい。利用者から「メモがある場合と無い場合で名前の位置が異なる。メモの内容も表示したい」との指摘があった。
- 実装上の原因は、2行目のCSSが`:first-child`／`:not(:first-child)`の位置指定で「1つ目はメモ、それ以外は表示名」と決めており、メモが無いと表示名が1つ目の要素になって規則が入れ替わることにある。
- 代替案として表示名を1行目のカテゴリ名の隣へ移す案（2行目をメモ専用にする）も検討したが、375pxで1行目にカテゴリ名・「収入」の印・複数名の表示名・金額が並ぶと省略が頻発するため採用しない。

## 対応

- 2行目は表示名（収入は「受取者 〇〇」）を先頭に固定し、メモがあればその後ろに続ける。表示名は2行目の左端に揃い、メモの有無で位置を変えない。`AC-HIS-007-1`と`AC-HIS-007-3`、画面仕様の行構成の記述を更新する。
- 表示名は本文色、メモは薄い色（`--muted`）で区別し、区切り文字は入れない。区切り文字を入れると`textContent`とアクセシブル名の断言へ影響するため。
- 表示名の上限7割、メモの残り幅での省略記号、メモが無い行で表示名が全幅を使う規則は維持する。CSSは位置指定ではなく要素ごとのクラス指定に変え、メモの有無で規則が入れ替わらないようにする。
- 行リンクのアクセシブル名（`AC-HIS-007-2`: 金額の後に表示名、末尾にメモ）は変更しない。DTO・query・Server Action・DBは変更しない。

## 安全性確認

presentationの並び順とCSSだけの変更で、認可、RLS、グループ分離、金額計算、楽観的ロックを変更しない。クライアントへ渡す情報は増えない。支払者は引き続き表示しない（`AC-TXN-018-3`）。

## 実装可能性確認

- `history-list.tsx`の`details`配列を表示名→メモの順へ入れ替え、各spanへ`history-row-party`／`history-row-memo`のクラスを付ける。
- `history.module.css`の`:first-child`規則を上記クラスへ置き換え、表示名は`flex: 0 1 auto; max-width: 70%`、メモは`flex: 1 1 auto; min-width: 0`とする。表示名だけの行は`max-width`を外して全幅を使えるようにする（`:only-child`または`data`属性）。
- component testで、メモがある行と無い行の両方で2行目の1つ目の要素が表示名であること、メモが表示名の後に続くことを断言する。

## MVP範囲確認

対象は履歴一覧の2行目の並び順と体裁のみ。1行目の構成、アクセシブル名、日別取引sheet、固定費一覧、分析の行構成は対象外とする。

## 判定

整合性、安全性、実装可能性とMVP範囲を確認し承認する。component test（メモあり・なしの両行で2行目の先頭が表示名、メモが後続、収入行は受取者が先頭）を先に更新し、375 x 812と320pxで横overflowと初期viewportの行数、1280 x 800の2カラムを実画面で確認する。

## 実装確認

`history-list.tsx`の2行目の`details`を表示名→メモの順へ入れ替え、各spanへ`history-row-party`／`history-row-memo`のクラスを付けた。`history.module.css`の`:first-child`／`:not(:first-child)`の位置指定を上記クラスへ置き換え、表示名は`flex: 0 0 auto; max-width: 70%`で本文色、メモは`flex: 1 1 auto`で残り幅を使い薄い色にした。表示名だけの行は`:only-child`で`max-width`を外す。初版で表示名を`flex: 0 1 auto`にしたところ長い表示名と長いメモが両方縮んで表示名が7割未満で切れたため、縮まない指定へ直した。アクセシブル名、DTO、query、Server Action、DBは変更していない。

component testへ「2行目はメモの有無にかかわらず表示名（受取者）が先頭でメモが後続」の断言を追加し、単体・component・architecture test（106ファイル1,005件）、lint、format、型検査、本番buildが成功。

fixtureの一時preview route（コミット前に削除）で修正前後を同じ架空データ（10件、5日付、1人・2人・3人の支出、収入、長いメモ、長い表示名）で撮影・計測した。2行目の1つ目のspanの左端座標（px）:

| 幅         | 修正前: メモあり行 / メモなし行 | 修正後: メモあり行 / メモなし行 | 初期viewport内の行 | 横overflow |
| ---------- | ------------------------------- | ------------------------------- | ------------------ | ---------- |
| 375 x 812  | 244（右端）/ 51                 | 51 / 51                         | 8件                | 0px        |
| 320 x 812  | 189（右端）/ 51                 | 51 / 51                         | 8件                | 0px        |
| 1280 x 800 | 1,085（右端）/ 578              | 578 / 578                       | 9件                | 0px        |

修正前はメモがある行だけ表示名が2行目の右端へ移っていたが、修正後は全行で表示名が左端に揃い、メモはその右に薄い色で続く。行の高さ（60px）、ページ高さ、初期viewportの行数は修正前と同じ。長い表示名と長いメモが並ぶ行は「山田・佐藤・とてもな…　歓迎会…」のように表示名が7割で切れ、メモは残り幅で読める。1280 x 800では2カラムを維持し、表示名の位置は375pxと同じ規則で揃う。
