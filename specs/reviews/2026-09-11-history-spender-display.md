# 履歴の支出行に支出した人を表示する

状態: 実装確認済み
レビュー日: 2026-09-11
ブランチ: feat/history-spender-display
対象仕様: `specs/01-product-requirements.md`、`specs/02-use-cases.md`、`specs/03-screen-specification.md`、`specs/07-acceptance-test-plan.md`、`specs/15-e2e-testing.md`
関連ID: `HIS-007`、`AC-HIS-007-1`〜`AC-HIS-007-3`を追加。`AC-HIS-006-2`、`AC-HIS-006-3`を更新。`TXN-018`、`AC-TXN-018-3`、`HIS-004`、`AC-HIS-003-3`、`AC-HIS-006-4`を参照（更新なし）。

## 指摘

- 旧レビュー`2026-09-09-history-dense-rows`で履歴の行を1〜2行へ圧縮した結果、1人の支出には誰の支出かが行に出なくなり、2人以上の支出も「2人で分割」と人数だけになった。収入は「受取者 〇〇」を表示しているのに、支出は行を見ても誰の支出か分からない。利用者から「履歴で支出者も表示したい」との要望があった。
- 「支出者」の意味を確認した結果、表示するのは`TXN-018`で隠した支払者ではなく、負担メンバー（画面の語では「支出した人」）である。支払者を画面へ戻す変更は行わない。
- 初版では「支出した人 山田」と見出し語を付けたが、利用者から「支出した人という文言はなくても良い」と指示があった。加えて、行リンクのアクセシブル名へ「支出した人」を含めると、E2E-004の`getByLabel("支出した人")`（絞り込みsheetのselect）が行リンクにも一致して失敗した。表示名だけを出す方針へ改めた。

## 対応

- `HIS-007`と`AC-HIS-007-1`〜`AC-HIS-007-3`を追加し、支出行の2行目へ支出した人の表示名だけ（「山田」「山田・佐藤」）を表示する。収入の「受取者 〇〇」と同じ位置・同じ体裁とし、「支出した人」の見出し語は付けない。
- 2人以上へ配分された支出は表示名を「・」で連結し、「2人で分割」の人数要約は廃止する。各人の金額は列挙しない（全員分の金額は日別取引sheetで確認する）。`AC-HIS-006-2`をこの規則へ更新する。
- 行リンクのアクセシブル名にも表示名を、受取者と同じ位置（金額の後、メモの前）で含める。「支出した人」の語は絞り込みsheetのラベルと重なるためアクセシブル名へ入れない。`AC-HIS-006-3`を更新する。
- メモと表示名が同じ行にあるときは、表示名を行幅の7割を上限に省略記号で切り、メモを残り幅で縮めて横overflowを出さない。メモが無い行では表示名が行幅全体を使う。
- 削除済みメンバーは既存の履歴用表示名の解決をそのまま使う。DTO・query・cursor・Server Action・DBは変更しない。

## 安全性確認

presentationとdomainの純関数だけの変更で、認可、RLS、グループ分離、金額計算、楽観的ロックを変更しない。表示名は既にDTOの`allocations`へ含まれており（旧レイアウトでは全員分を列挙していた）、クライアントへ渡す情報は増えない。支払者（`partyDisplayName`の支出側）は引き続き表示しない。

## 実装可能性確認

- `HistoryRow.allocations`の`displayName`を連結するだけで表示でき、`summarizeHistoryAllocations`を表示名の連結を返す関数へ置き換える。`buildHistoryRowAccessibleName`は受取者と同じ分岐へ表示名を足す。
- `history-list.tsx`は2行目の`details`の`split`項目を表示名へ置き換える変更に限る。CSSは2行目のspanの縮み方（メモ以外を7割上限で省略記号、メモは残り幅）だけを変える。
- 既存のdomain test・component test・E2E-004の「2人で分割」の断言を表示名の列挙へ更新する。allocationの順序はDBの返却順に依存するため、E2Eでは両メンバーの表示名が含まれることを順序に依存せず確認し、「支出した人」「人で分割」が行に無いことを確認する。

## MVP範囲確認

対象は履歴一覧の支出行の2行目とアクセシブル名。支払者の表示、日別取引sheet・固定費一覧・分析の変更、各人の金額の履歴への再掲、表示名の並び順の変更は対象外とする。

## 判定

整合性、安全性、実装可能性とMVP範囲を確認し承認する。domainの純関数test（表示名の連結、アクセシブル名）とcomponent test（1人・2人の支出行の表示、「支出した人」「2人で分割」の不在、メモ併記）を先に更新し、375 x 812で初期viewportの行数と320pxの横overflow、1280 x 800の2カラムを実画面で確認する。

## 実装確認

`history-row-label.ts`の`summarizeHistoryAllocations`を`describeHistorySpenders`（「山田・佐藤」）と`describeHistoryParty`（支出なら表示名、収入なら「受取者 〇〇」）へ置き換え、`history-list.tsx`の2行目とアクセシブル名で同じ文言を使うようにした。CSSは2行目のspanの縮み方だけを変え、メモ以外のspanは行幅の70%を上限に省略記号で切る。DTO・query・cursor・Server Action・DBは変更していない。

architecture test、単体・component test（domain test 3件を更新、component testの断言を表示名・アクセシブル名へ更新）、lint、format、型検査、本番buildが成功。E2E-004は「2人で分割」の断言を両メンバーの表示名の存在と「支出した人」「人で分割」の不在へ更新し、PRのCIで実行する。初版のCIでは行リンクのアクセシブル名に含めた「支出した人」がsheetの`getByLabel("支出した人")`と衝突してE2E-004が失敗したため、見出し語を外した。

fixtureの一時preview routeで修正前後を同じ架空データ（10件、8日付、1人・2人・3人の支出、収入、長いメモ、長い表示名）で撮影・計測した:

| 幅         | 修正前: 初期viewport内の行 / 行の高さ / ページ高さ | 修正後: 初期viewport内の行 / 行の高さ / ページ高さ | 横overflow |
| ---------- | -------------------------------------------------- | -------------------------------------------------- | ---------- |
| 375 x 812  | 7件 / 44・60px / 1,108px                           | 7件 / 60px / 1,157px                               | 0px        |
| 320 x 812  | 7件 / 44・60px / 1,108px                           | 7件 / 60px / 1,157px                               | 0px        |
| 1280 x 800 | 9件 / 44・60px / 994px                             | 8件 / 60px / 1,043px                               | 0px        |

メモが無い1人の支出行は2行目が増えるため44px→60pxになり、10件で約50px（1行分）ページが長くなる。日付見出しが8つある本fixtureでは初期viewportの行数は7件で修正前と同じだった（`AC-HIS-006-4`の8件目標は日付見出しの数に依存し、旧レビューと同じ条件では変わらない）。メモ併記時は「歓迎会」と「山田・佐藤・とて…」（70%上限）のように両方が読め、長い表示名だけの行は省略記号で切れる。member指定時は主金額・「取引全体」の補足の下に「山田・佐藤」が並び、1280 x 800では2カラムを維持した。見出し語を外した後も行の構成・高さは同じで、表示名の幅だけが短くなる。一時previewはコミット前に削除した。
