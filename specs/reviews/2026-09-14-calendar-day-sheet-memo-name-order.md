# 日別取引sheetの2行目を履歴と同じ「表示名→メモ」の順にそろえる

状態: 実装確認済み
レビュー日: 2026-09-14
ブランチ: fix/calendar-day-sheet-memo-name-order
対象仕様: `specs/02-use-cases.md`、`specs/03-screen-specification.md`、`specs/07-acceptance-test-plan.md`
関連ID: `AC-CAL-005-1`、`AC-CAL-005-2`、`AC-CAL-017-1`を更新。`CAL-017`、`AC-CAL-017-2`、`AC-HIS-007-1`、`AC-HIS-007-3`、`AC-TXN-018-3`を参照（追加なし）。

## 指摘

- 履歴一覧は`2026-09-13-history-memo-name-order`で2行目を「表示名→メモ」の順へ直したが、カレンダーの日別取引sheetは「メモ→表示名」の順のままである。`AC-CAL-017-1`と画面仕様§5「取引の行構成（CAL-017）」は「履歴の行（§7）と見た目・情報の順序をそろえる」と定めているため、現状は仕様どおりでない。
- 利用者からも、日別sheetではメモが先に出て名前が後に来るため履歴と並びが違う、という指摘があった。
- 実装上の原因は履歴と同じで、`calendar.module.css`の2行目が`:first-child`／`:not(:first-child)`という位置指定で「1つ目はメモ、それ以外は表示名」と決めていることにある。メモが無い行では表示名が1つ目の要素になり、幅の規則まで入れ替わる。そのためメモがある行だけ表示名が2行目の右端へ押し出され、同じ一覧の中で表示名の位置が行ごとに左右へ動く。

## 対応

- 日別取引sheetの2行目を、表示名（収入は「受取者 〇〇」）を先頭に固定し、メモがあればその後ろに続ける順序へ変更する。履歴（`AC-HIS-007-3`）と同じ規則にそろえる。
- 表示名は本文色、メモは薄い色（`--muted`）で区別し、区切り文字は入れない。区切り文字は`textContent`とアクセシブル名の断言へ影響するため。
- 表示名の上限7割、メモの残り幅での省略記号、メモが無い行で表示名が全幅を使う規則は履歴と同じにする。CSSは位置指定ではなく要素ごとのクラス指定へ変え、メモの有無で規則が入れ替わらないようにする。
- `AC-CAL-017-1`、`AC-CAL-005-1`、`AC-CAL-005-2`（固定費の名称の行の前後関係の記述）と画面仕様の行構成、受け入れテスト計画の該当項目を更新する。
- 行リンクのアクセシブル名（`AC-CAL-017-2`: 金額の後に表示名、末尾にメモ全文）は変更しない。DTO、query、Server Action、DBは変更しない。

## 安全性確認

presentationの並び順とCSSだけの変更で、認可、RLS、グループ分離、金額計算、楽観的ロックを変更しない。クライアントへ渡す情報は増えない。支出の支払者は引き続き表示しない（`AC-TXN-018-3`）。固定費の展開行の遷移先（`AC-REC-002-3`）も変えない。

## 実装可能性確認

- `calendar-day-explorer.tsx`の`details`配列を表示名→メモの順へ入れ替え、`isMemo`のbool分岐をやめて各spanへ`calendar-transaction-party`／`calendar-transaction-memo`のクラスを付ける。既存testが参照する`.calendar-transaction-memo`はメモ側のクラス名として維持する。
- `calendar.module.css`の`:first-child`／`:not(:first-child)`規則を上記クラスへ置き換える。表示名は`flex: 0 0 auto; max-width: 70%`で本文色、メモは`flex: 1 1 auto`で残り幅を使う。表示名だけの行は`:only-child`で`max-width`を外す。履歴で`flex: 0 1 auto`にすると表示名とメモが両方縮んで表示名が7割未満で切れた経緯があるため、縮まない指定を最初から採る。
- component testで、メモがある行と無い行の両方で2行目の1つ目の要素が表示名であること、メモが表示名の後に続くこと、収入行は受取者が先頭であることを断言する。

## MVP範囲確認

対象は日別取引sheetの2行目の並び順と体裁のみ。1行目の構成、固定費の名称の行、アクセシブル名、金額の表示規則、履歴・固定費一覧・分析の行構成は対象外とする。

## 判定

整合性、安全性、実装可能性とMVP範囲を確認し承認する。component test（メモあり・なしの両行で2行目の先頭が表示名、メモが後続、収入行は受取者が先頭）を先に更新し、375 x 812と320pxで横overflowとsheet高さ、1280 x 800の右カラムを実画面で確認する。

## 実装確認

`calendar-day-explorer.tsx`の2行目の`details`を表示名→メモの順へ入れ替え、`isMemo`のbool分岐をやめて各spanへ`calendar-transaction-party`／`calendar-transaction-memo`のクラスを付けた。`calendar.module.css`の`:first-child`／`:not(:first-child)`の位置指定を上記クラスへ置き換え、表示名は`flex: 0 0 auto; max-width: 70%`で本文色、メモは`flex: 1 1 auto`で残り幅を使い薄い色（`--muted`）にした。表示名だけの行は`:only-child`で`max-width`を外す。アクセシブル名、DTO、query、Server Action、DBは変更していない。

component testへ「2行目はメモの有無にかかわらず表示名（受取者）が先頭でメモが後続」の断言を追加し、単体・component・architecture test（110ファイル1,065件 + architecture 217件）、lint、format check、型検査、本番buildが成功。

fixtureの一時preview route（コミット前に削除）で修正前後を同じ架空データ（支出4件・収入2件、メモあり／なし、1人・2人・3人の支出、長い表示名、長いメモ、固定費の展開行）で撮影・計測した。2行目の1つ目のspanの左端座標（px）:

| ---------- | -------------------------------- | ------------------------------- | --------- | ---------- |
| 375 x 812  | 254・205・185（右側）/ 42        | 42 / 42                         | 529px     | 0px        |
| 320 x 812  | 199・150・130（右側）/ 42        | 42 / 42                         | 556px     | 0px        |
| 1280 x 800 | 1,079・1,030・1,010（右側）/ 918 | 918 / 918                       | 556px     | 0px        |

修正前はメモがある行だけ表示名が2行目の右側へ押し出され、メモが無い行では左端にあった。修正後は全行で表示名が左端に揃い、メモはその右に薄い色で続く。行の高さ（通常60px、固定費の展開行83px）、sheet高さ、初期viewportに収まる行数は修正前と同じ。長い表示名と長いメモが並ぶ行は375pxで表示名が166px（行幅の約7割）で省略記号に切られ、メモは残り幅で読める。1280 x 800では右カラムに同じ行構成が出て、表示名の位置は375pxと同じ規則で揃う。履歴一覧（`2026-09-13-history-memo-name-order`）と並びと配色が一致することを同じ幅で確認した。
