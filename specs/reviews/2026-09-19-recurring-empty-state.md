# 固定費画面のheader「ホームへ戻る」重複と0件時の空状態表示

状態: 実装確認済み
レビュー日: 2026-09-19
ブランチ: fix/recurring-empty-state
対象仕様: `specs/02-use-cases.md`、`specs/03-screen-specification.md`、`specs/07-acceptance-test-plan.md`、`specs/14-recurring-transactions.md`、`specs/15-e2e-testing.md`
関連ID: `AC-REC-004-2`を追加。`REC-001`、`REC-004`、`NAV-004`、`AC-NAV-001-4`、`AC-NAV-004-2`、`AC-REC-004-1`、`E2E-009`を参照。

## 指摘

- Issue #148。固定費画面（`/groups/{groupId}/recurring-transactions`）のheader右上に「ホームへ戻る」リンクがある。画面仕様§2は共通ナビゲーションを表示する画面のheaderに同じ画面間移動を重複表示しないと定め（`AC-NAV-001-4`）、同じ設定配下のメンバー・カテゴリ画面はCSSで隠し、予算画面はそもそも置いていない。固定費画面だけが表示されたままで仕様どおりでない。
- 固定費が0件のとき、「登録済みの固定費」の見出しの下に長い説明文だけが表示される。画面仕様§10と固定費仕様§7は「登録できる内容が分かる空状態」と定めているが、空であることと「下のフォームから追加する」という次の操作が伝わらない。説明文は画面上部の説明とほぼ同じ内容の重複でもある。
- 空状態の具体的な文言と導線が仕様に無く、テストでも固定されていなかった。

## 対応

- 固定費画面のheaderから「ホームへ戻る」を削除し、グループ名と画面名だけにする。CSSで隠すのではなくmarkupから外す。画面仕様§10と固定費仕様§7へ「headerに共通ナビゲーションと重複する画面間移動を置かない」を明記する。
- 0件のときは一覧の位置に「固定費はまだありません」と、登録できる内容が分かる1文の説明（家賃や給与など毎月同じ日・同じ金額の取引）を表示する。owner/adminには同じ空状態の中に作成フォームへ移動するリンク「固定費を追加する」を置き、フォームの先頭までscrollさせる。memberにはリンクを出さず、既存の「固定費の設定はオーナーと管理者が行います。」だけを示す。1件以上あるときは空状態を出さず、一覧を先頭に置く現行の順序を保つ。
- フォームを先頭へ移す案は採らない。1280 x 800では一覧とフォームが2カラムで並び順序の意味が薄く、375 x 812でも件数によって画面構成が入れ替わると再訪時の位置記憶を崩すため。
- `AC-REC-004-2`を追加し、`E2E-009`の関連IDへ加える。受け入れテスト計画へcomponent test・architecture testの確認項目を追記する。

## 安全性確認

presentationのmarkupとCSSだけの変更で、認可、RLS、グループ分離、金額計算、楽観的ロックを変更しない。空状態のリンクは`view.canManage`（サーバーが権限から算出する既存のフラグ）で出し分けるが、作成フォーム自体の表示条件とServer Action・DB関数の権限確認は変更しないため、memberがリンクを見ても見なくても作成はできない。クライアントへ渡す情報は増えない。

## 実装可能性確認

- `page.tsx`から`Link`のimportと「ホームへ戻る」を削除する。他画面の`.text-link`をCSSで隠す規則は既存のarchitecture testが参照するため変更しない。
- `recurring-management.tsx`の0件分岐を、見出し文・説明・リンクを持つ空状態へ置き換える。リンクは同一ページ内の`href="#recurring-create-form"`とし、作成フォームのsectionへ同じ`id`を付ける。作成フォームは`canManage`のときだけ描画するため、リンクも`canManage`のときだけ出す。
- `recurring.module.css`へ空状態の見出し・説明の体裁を追加し、色は`styles.css`のtoken（`--text`、`--muted`）だけを使う。リンクは共通の`secondary-link`（44px以上）を使う。
- component testで、0件・owner、0件・member、1件以上の3状態を断言する。architecture testで`page.tsx`に「ホームへ戻る」と`next/link`のimportが無いことを断言する。`E2E-009`で登録前の空状態とリンク、header、登録後に空状態が消えることを確認する。

## MVP範囲確認

対象は固定費画面のheaderと0件時の空状態のみ。メンバー・カテゴリ画面の`.text-link`（CSSで隠している既存方式）、固定費フォーム、一覧カード、カレンダーの展開表示は対象外とする。

## 判定

整合性、安全性、実装可能性とMVP範囲を確認し承認する。component test（0件・owner、0件・member、1件以上）とarchitecture test（headerの「ホームへ戻る」不在）を先に追加し、375 x 812と320pxで空状態とリンク押下後のフォーム位置、1280 x 800の2カラムを実画面で確認する。

## 実装確認

`page.tsx`から`next/link`のimportと「ホームへ戻る」を削除し、headerをグループ名と画面名だけにした。`recurring-management.tsx`の0件分岐を、「固定費はまだありません」の見出し文、「家賃や給与など、毎月同じ日・同じ金額の取引を登録できます。」の1文、owner/adminだけに出す`secondary-link`の「固定費を追加する」（`href="#recurring-create-form"`）へ置き換え、作成フォームのsectionへ同じ`id`を付けた。`recurring.module.css`へ空状態の中央寄せと見出し・説明の体裁（色は`--text`・`--muted`のtoken）を追加し、panelへ`scroll-margin-top`を付けて移動後の上端に余白を残した。DTO、query、Server Action、DBは変更していない。

component testへ0件・owner（見出し・1文の説明・リンクと遷移先id）、0件・member（リンクとフォームが無く読み取り専用の文言だけ）、1件以上（空状態なし・一覧あり）の3件、architecture testへheaderの「ホームへ戻る」と`next/link`の不在・空状態markupの存在の1件を追加し、`E2E-009`へ登録前の空状態・リンク押下でフォーム見出しがviewport内に入ること・登録後に空状態が消えること・headerにリンクが無いことの断言を追加した。単体・component test 112ファイル1,094件、architecture test 229件、lint、format check、型検査、本番buildが成功。E2Eはローカルで未実行（CIで確認する）。
