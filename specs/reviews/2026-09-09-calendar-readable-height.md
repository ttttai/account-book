# ホームカレンダーの行高配分と日別金額の可読性

状態: 実装確認済み
レビュー日: 2026-09-09
ブランチ: fix/calendar-readable-height
対象仕様: `specs/02-use-cases.md`、`specs/03-screen-specification.md`、`specs/07-acceptance-test-plan.md`、`specs/15-e2e-testing.md`
関連ID: `CAL-002`、`CAL-012`、`NAV-002`、`AC-CAL-012-5`、`AC-NAV-002-2`、`AC-CAL-001-20`（追加）、`E2E-012`（追加）

## 指摘

Issue #133。`03-screen-specification.md` §5は「カレンダー行は`100dvh`から他要素を除いた高さを6行で分ける」と定めているが、実装の`.calendar-cell`は`clamp(44px, calc((100dvh - 30rem) / 6), 56px)`で行高の上限を56pxに固定し、日別金額は`clamp(0.5rem, 2.4vw, 0.72rem)`でviewport幅だけから決まっていた。その結果、375 x 812では金額9pxでカレンダー下に約300pxの空白が残り、320 x 568では8px、1280 x 800では約10pxの金額に対して余白だけが広がっていた。仕様は配分の原則を述べるだけで、行高の上限の有無、金額サイズの下限と拡大規則、確認する数値を持っていなかった。

## 対応

- `AC-CAL-001-20`を追加し、6行が残り高さを均等に分け合うこと、行高に固定上限を設けないこと、375 x 812での表下端から下部ナビゲーションまでの空き（32px以内）と行高の差（2px以内）、行の下限44pxと高さ不足時の縦スクロール、金額の文字サイズ（375pxで11px以上、1280 x 800で16px以上、320pxで`+999,999`が1行）を受け入れ条件にした。
- `03-screen-specification.md` §5「カレンダーの日付セル」へ「行高と金額の大きさ」を追記し、表がホーム本文の残り高さを受け取って曜日見出しを固定・6行へ均等配分すること、下限を超える行だけを広げること、金額サイズを表の幅から算出して下限0.5rem・上限1.125remとすること、日番号・曜日見出し・月間合計の文字サイズは変えないことを定めた。
- `07-acceptance-test-plan.md`へarchitecture test・`E2E-012`・実画面確認の項目を追加し、`15-e2e-testing.md`へ`E2E-012`（3 viewportで高さ・文字サイズ・幅の収まりを測定）を追加した。
- `README.md`のバージョンを0.3.26へ更新した。

## 安全性確認

- CSSと測定テストだけの変更で、認証・認可・集計・データ取得・日付選択・URL同期・accessibility nameを変更しない。Client Componentへ渡すDTOも変わらない。
- 行の下限44pxはタップ領域の要件（`NFR-UI`の44 x 44）を維持し、高さ不足時は欠落・重なりではなく縦スクロールへ切り替える（`AC-NAV-002-3`）。
- 金額サイズの算出は`+999,999`が320pxのセルに1行で収まる比率を基準にし、`AC-CAL-012-5`（6桁以下は折り返さない、桁の途中で分断しない）を壊さない。

## 実装可能性確認

- 表をホーム本文（flex column）の残り高さを受け取るflex itemにし、tbodyの各行へ`height: calc(100% / 6)`を与えると、Blink・WebKitともに余った高さをtbodyの百分率行へ配分し、曜日見出し（固定高さ）には配分しない。Chromiumのprototype測定で、375 x 812は6行が81.9〜82.3px、1280 x 800は79.9〜80.5px、320 x 568は下限44px（支出と収入を含む行だけ54.6px）になり、ページ幅を超える横スクロールは発生しなかった。
- container query単位（`cqb`）で行高を算出する案は、Chromiumでflex成長後に単位が再解決されず行高が下限に留まったため採用しない。
- 金額サイズは`.calendar-card`を`container-type: inline-size`とし、`clamp(0.5rem, calc((100cqi - 8px) / 27.8), 1.125rem)`で算出する。除数27.8は「`+999,999`（8文字、Arial Bold・`letter-spacing: -0.04em`）の幅 ≒ 3.88em × 7列 ≒ 27.2」に約2%の余裕を足した値で、セルの`border-spacing`を1pxへ、選択枠を`border`から`box-shadow: inset`へ変えてセル幅を確保する。
- 日別パネルを開いた1280pxではカードが狭くなるが、上限1.125remに達するため16px以上を維持する。

## MVP範囲確認

ホームカレンダーの表と、その外枠（`.calendar-home-page`・`.calendar-card`）の高さ配分に限定する。日別取引sheet、集計領域、履歴、他画面のレイアウト、日番号・曜日見出し・月間合計の文字サイズは変更しない。

## 判定

`CAL-002`、`CAL-012`、`NAV-002`、`AC-CAL-012-5`、`AC-NAV-002-2`・`AC-NAV-002-3`、`NFR-UI-*`と整合し、安全かつ実装可能である。次の順で実装を承認する。

1. architecture test（`tests/architecture/navigation-foundation.test.mjs`・`calendar-foundation.test.mjs`）で、行高の固定上限を持たないこと、tbody行の百分率配分、金額サイズの算出式と下限・上限を先に固定する。
2. `E2E-012`（`tests/e2e/calendar-readable-height.spec.ts`）で375 x 812・320 x 568・1280 x 800の高さ・文字サイズ・幅の収まりを測定する。
3. CSSを実装し、375 x 812・320 x 568・1280 x 800の実画面（スクリーンショット）で表の下の空き・金額の大きさ・`+999,999`の1行表示を確認する。

- 状態を実装確認済みへ更新（2026-09-10）。
